# 문서 작성·관리 UX 크리틱 — 2026-10-08

## 1. 결론

- **C 권고: 범용 문서 작성·위키 확장은 중단하고, 외부 문서 연결 + 내부 회의 기록만 남긴다.** 유달리의 가치는 업무·결정·태스크를 연결하는 데 있고, 현재 편집기는 노션을 대체할 신뢰성과 문서 호환성을 갖추지 못했다.
- “전부 최악”은 과하다. 인라인 편집·슬래시 메뉴·자동 저장·Markdown 링크·백링크·복원은 작동했다. 그러나 모바일 탐색 단절과 가져오기 결과의 의미 손실은 단순한 미관 문제가 아니다.
- B를 그대로 적용하면 음성 회의록과 AI 문서 문맥도 함께 잃는다. A는 작은 UI 개선이 아니라 별도 편집기 제품 개발이다.
- 검증: 로컬 `127.0.0.1:8765`, 운영 `udally.sio2.kr`, Chromium/Playwright의 실제 CSS 뷰포트 1440×1000·390×844. 운영은 로그인 이후 GET/HEAD/OPTIONS만 허용했고 데이터 변경 요청은 없었다. 운영 캡처의 회색 영역과 본문 넘침 클리핑은 개인정보·본문 마스킹이다.

### 노션 ZIP 가져오기: 구조가 어떻게 달라졌는가

- 사용자 설명의 원본은 **페이지 안 DB 표→행 페이지**다. Notion 내보내기는 일반 페이지를 Markdown, DB를 CSV와 행별 Markdown으로 나눈다. [Notion 공식 내보내기 설명](https://www.notion.com/help/export-your-content)
- **상:** `/docs/18`에는 CSV 참조 1개와 외부 노션 URL 6개가 남았다. `/docs/20`은 **본문 0자·하위 3개**의 빈 문서다. `/docs/24`는 **CSV 참조 8개·하위 8개**인데, 본문에 실제 표와 클릭 가능한 링크가 모두 0개다. [prod-doc18-1440.png](shots/prod-doc18-1440.png), [prod-doc20-1440.png](shots/prod-doc20-1440.png), [prod-doc24-1440.png](shots/prod-doc24-1440.png)
- **상:** `/docs/24` 문서 폭은 1440 화면에서 **1744px**, 390 화면에서 **1394px**까지 넘쳤다. `/docs/18`도 모바일 **663px**. 긴 변환 잔재가 읽기를 방해한다. [prod-doc24-390.png](shots/prod-doc24-390.png)
- 코드로 설명되는 원인: ZIP에서 `.md`만 읽고 CSV는 제외하며, Markdown 없는 폴더는 빈 문서로 합성한다. 상대 `.md`만 내부 링크로 바꾸고 CSV 참조·절대 노션 URL은 남긴다. 행 속성도 필드가 아니라 글머리 텍스트가 된다. `core/projects/docs.py:597,621,659,712`
- **판단:** 파일 계층 일부는 보존됐지만, ‘표에서 행 찾기’가 ‘빈 문서와 깊은 트리 뒤지기’로 바뀌었다. 85개 생성은 이전 성공을 보증하지 않는다. 설계의 ‘링크로 남길 이유가 없어진다’ 기준과도 어긋난다(`docs/IMPL-PLAN-11.md:435`). 원본 ZIP·노션 원화면 없이 정확한 누락률은 판정할 수 없다.

## 4. 권고안 상세

- **남길 것:** 회의록·전사문·초안→확정·결정/태스크 연결, 간단한 텍스트 정정, 저장/복구, 내부 권한. 음성 흐름이 `Doc(kind=meeting)`에 의존하므로 모델을 지우지 않는다. `core/notes/models.py:26`, `core/notes/services.py:202,409,437`
- **버릴 것:** 새 범용 위키·노션 대체 선언·DB 복제·범용 문서 트리 확장. 현재 ‘Notion ZIP 가져오기’를 정상 이전처럼 제공하는 것도 중단한다.
- **대체할 것:** 프로젝트/태스크의 ‘자료’에서 URL·표시명·출처·담당자·용도를 관리하고 원본에서 편집한다. 이미 외부 링크/산출물 연결 기반이 있다. 미리보기는 접근 가능한 정보만 제공하며, 링크 등록이 외부 권한이나 본문 검색을 제공한다고 약속하지 않는다. `core/web/templates/tasks/_refs.html:1,20,42`
- **MCP·스킬:** 기존 `list_docs/get_doc`와 ID는 아카이브 읽기로 유지. 범용 `create_doc/update_doc/import_docs`는 단계적으로 종료하고, 회의록 정정과 외부 자료 연결 도구로 분리한다. URL만으로 AI가 비공개 노션을 읽을 수는 없으므로 별도 인증 연결 또는 승인된 문맥 사본이 필요하다. `mcp_server/mcp_server/server.py:33,937,972,1004,1047`; `skills/pm/SKILL.md:91,121`
- **백링크:** 내부 회의/아카이브 연결은 유지, 외부 자료는 ‘어떤 태스크에서 참조하는지’만 집계한다. 외부 노션 본문 역참조는 연동 없이는 제공하지 않는다.
- **기존 데이터:** 85개를 삭제하거나 자동 재수입하지 않는다. 원본 ZIP·현재 Markdown·첨부·이력·권한·ID 연결을 보존하고 읽기 전용 표시, 원본 URL 대응표를 만든다. 원본 없는 내부 고유 글은 수동 내보내기·검수 후 이전한다. 빈 문서도 자식/연결 확인 전 삭제하지 않는다.
- **투자 순서:** 모바일 목록 복귀·가로 넘침·제목 저장 표시부터 고친 뒤, 외부 자료 목록과 아카이브 전환. 이후 회의 기록 편집만 개선한다.
- 업무 도구의 적정 범위는 제품 목적에 달린다. [Linear](https://linear.app/docs/documents)는 프로젝트 문서와 연결을, [GitHub Wiki](https://docs.github.com/en/communities/documenting-your-project-with-wikis/about-wikis)는 저장소 지식을, [Jira–Confluence](https://support.atlassian.com/jira-cloud-administration/docs/integrate-with-confluence/)는 전문 문서 도구와 업무 연결을 제공한다. 유달리에는 마지막 방식과 내부 회의 기록의 조합이 적합하다. 이는 제품 판단이며 사용자 수요 검증은 별도다.

## 5. 확인 불가

- 노션 원본 화면·원본 ZIP, 실제 노션/옵시디언 계정에서의 비교 조작은 확인 불가. 비교는 공식 문서 기준이며 원본과의 픽셀·행 단위 대조가 아니다.
- 로컬 프로젝트의 태스크가 0개여서 **태스크 연결 성공은 확인 불가**. 문서 쪽 입력 화면·태스크 쪽 연결 코드는 확인했다. 운영 연결 버튼은 누르지 않았다.
- 실제 음성 녹음→전사, 다인 동시 편집, 장시간 오프라인 복구, 실기기 터치/가상 키보드/한국어 IME, 부하 테스트는 미실시. 스크린샷은 모바일 폭 에뮬레이션이다.
- 운영 배포 코드와 로컬 코드의 완전 일치는 검증하지 않았다. 가져오기 원인은 관찰 결과와 로컬 구현이 일치한다는 수준이다.
