## 4. 안정성 (md2 == md3)

- 기본 구성: 81개 중 76개가 첫 저장 뒤 바로 고정점이다. 4, 7, 11, 18은 두 번째 저장에서 빈 줄과 공백만 바뀐 뒤 멈춘다(18은 연속 빈 문단이 `&nbsp;`로 바뀐다).
- **22는 6회 왕복해도 고정점에 닿지 않는다.** 번호 목록 안 코드 블록 들여쓰기 버그로 저장할 때마다 코드 줄 앞에 공백이 1칸씩 늘어난다. 첫 저장 결과(md2)의 코드 내용은 원문과 같고, 두 번째 저장부터 바뀐다.
- 완화 A만 넣었을 때도 같다. 완화 B(1줄 패치)를 넣으면 22의 코드 내용 변화가 없어지고 남는 불안정은 빈 줄과 공백뿐이다.
- 그러므로 "처음 열 때 한 번만 정규화" 전략은 B 패치가 있어야 성립한다. B가 있으면 첫 저장에서 표기가 한 번 바뀌고 이후 사실상 고정된다.

## 5. 정규화 완화 시험

`@tiptap/markdown` 옵션은 `indentation`, `marked`, `markedOptions` 세 가지뿐이다(`node_modules/@tiptap/markdown/src/Extension.ts:68-87`). 이스케이프와 엔티티는 옵션으로 끌 수 없고, 노드·마크별 `renderMarkdown`/`parseMarkdown`을 바꾸거나 `MarkdownManager`의 메서드를 바꿔야 한다.

**완화 A** (`variant-a.mjs`, 확장 교체 + 메서드 교체 + 전처리)
1. CodeBlock `parseMarkdown`: `token.raw.trimStart()`로 펜스 판정 → 문서 23의 코드 블록 3개 복구
2. Link `renderMarkdown`: 링크 글자(`ctx.meta.markText`)가 href와 같으면 맨 URL로 출력 → 자동 링크 변환 17개 → 0개
3. `editor.storage.markdown.manager.encodeTextForMarkdown` 교체: `&`는 `&이름;` 꼴 앞에서만, `<`는 태그처럼 보일 때만 엔티티로 바꾼다. `_`는 단어 경계에서만, `~`는 `~~`일 때만 이스케이프한다 → 엔티티 3개 → 0개, 이스케이프 20개 → 6개. 공개 API가 아닌 private 메서드라 버전을 올릴 때마다 확인해야 한다
4. 불러오기 전처리: 코드 밖 홑물결 `~` → `\~` → 문서 22의 취소선 오변환 해결. 저장할 땐 홑물결을 이스케이프하지 않아 원문 표기가 유지된다

결과: 완전 일치 45 → 54, 의미 손실 4 → 3(코드 내용 누적 변화는 B가 필요).

**완화 B** (A + `@tiptap/extension-list` dist의 `indentLevel + marker.length + 1` → `+ 2`, 시험 뒤 원복)
- 번호 목록 안 코드 블록 공백 누적이 사라진다. 가상 예시 `1.`, `10.` 모두 그대로 왕복한다.
- 의미 손실은 `<aside>` 3건만 남는다.
- 정식으로 넣으려면 patch-package 또는 업스트림 수정을 기다려야 한다. 구분자 뒤 공백이 2칸 이상이면 `+ 2`로도 부족하므로, 실제 패치는 정규식 매치 길이로 계산해야 한다.

**시험하지 않은 것**: `<aside>` Callout 노드, 표 열 맞춤 끄기(TableKit 렌더러 교체), `[`·`]` 이스케이프 축소, `indentation.size: 4`.

**운영 권고**
- 사용자가 편집하지 않았으면 저장하지 않는다(dirty 검사). 열어 보기만 해도 표기가 바뀌는 일을 막는다.
- 첫 저장 때 표기 변화가 한 번 생긴다는 점(빈 줄·들여쓰기·표 맞춤)을 받아들이고, 변경 이력(DocRevision)에서 "형식 정리" 저장임이 드러나게 한다.
