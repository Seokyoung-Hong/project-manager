3. 이후 사용자가 UI/UX 텍스트와 메시지를 **전부 검토**하라고 요청했다. 이 단계는 검토로 진행했으며 문구 수정은 하지 않았다.
4. 특히 버튼에 대해 다음 기준을 추가했다. 이 검토는 아직 완료하지 못했다.

5. 마지막 지시: **“지금 지시하는 내용, 진행하고 있는 내용 전부 문서화 해. 다른 세션에서 진행할거야.”** 따라서 추가 구현보다 인수인계를 우선했다.

버튼 검토의 작업 기준은 `사용자 목적 → 예상 결과 → 실제 이동 화면/동작 → 권장 문구`다. 페이지 이동, 모달 열기, 패널 펼치기, 데이터 변경, 외부 서비스의 후속 단계를 구분한다. 단순히 목적지 이름을 붙이거나 모든 문구를 길게 만드는 방식은 피한다. 주변 문맥이 충분한 탭은 짧게 유지할 수 있다. 아직 구현하지 않은 결과를 약속하지 않는다.

중요한 지적:

- 실패 안내 누락: 문서·회의록 생성/업로드/삭제 오류를 버림, 잘못된 초대 만료 기간을 7일로 대체해 발급.
- 실제 결과와 다른 성공/실패 안내: GET 오류도 저장 실패로 표시, 복사 취소 후 성공 표시, GitHub 일부 동기화 실패 후 전체 성공처럼 표시.
- 자동 저장 실패/충돌에서 원인과 작성 내용 보존 안내 부족.
- 토큰의 인증 방식과 AI용 정책, OAuth 권한 범위 설명 부족.
- 실제 데이터 범위와 다른 문구: 회의록의 팀 공통은 조직 공통, 부하 요약의 필터 범위/분모, 검색은 제목·프로젝트명·태스크 ID 대상이며 본문 검색 아님.
- 실제 절차와 다른 문구: 포트폴리오 초안은 외부 AI 요청문 단계, Discord 연결은 코드 발급 이후 DM 단계, 초대는 로그인 후 별도 참여 확인.
- 설정 도움말의 날짜 제안은 현재 소비 코드가 확인되지 않음. 기능 여부를 정리해야 하며 문구만으로 작동을 약속하면 안 됨.
- 기한/목표일 용어, 진행 메모 저장 시점, 의존 방향, 삭제·보관 결과, 접근성 이름의 구체성 등.

서버 오류 지적은 소스 분기 확인 결과이며 전부 브라우저에서 재현한 것은 아니다. 토큰 발급/폐기, OAuth 허용, 초대 발급, 삭제, 외부 요청을 검토 명목으로 실행하지 않았다. 최신 외부 AI 클라이언트의 UI 명칭/명령은 별도 확인하지 않았다.
