## 통합 순서

1. **병렬 구현:** 각 세션은 자기 브랜치에서 작업한다. 기존 상대 세션을 재시작하거나 새 중복 담당자를 띄우지 않는다.
2. **교환할 증거:** 완료 commit, 수정 파일, 마이그레이션 목록·순서, 환경 설정, 테스트 결과와 검증 제한. 현재 작업 중인 상대 세션에 보낸 메시지만으로 수신·동의를 확정하지 않는다.
3. **공통 파일 통합:** 최신 main을 기준으로 별도 통합 브랜치에서 두 변경을 합친다. 전체 파일 덮어쓰기 대신 기능별로 수동 통합한다. 충돌 후보는 `web/urls.py`, `templates/base.html`, `views/teams.py`, `views/orgs.py`, `github/services.py`, `github/writes.py`다. 협업 API·권한 정책과 연동 재시도 훅을 함께 보존한다.
4. **마이그레이션:** 그래프·동일 번호 충돌을 확인하고 필요한 의존성 조정만 한다. 빈 검증 DB에 전체 적용하고 모델/마이그레이션 차이를 확인한다. 실제 운영 적용은 이 단계에 포함하지 않는다.
5. **통합 검증:** core 전체, Discord 서비스, 바뀐 MCP/클라이언트 검사를 실행한다. Astra가 요청 화면·팀 화면·이슈 Markdown·도움말·Discord 상태/허용/철회와 실패 상태를 로컬 Docker에서 검증한다. mock 검증과 실제 외부 연동 검증을 구분한다.
6. **운영 반영:** 통합 산출물과 검증 결과가 준비된 뒤 한 버전을 배포 대상으로 삼는다. 이번 요청은 운영 배포를 새로 지시하지 않았으므로 현재 배포는 수행하지 않는다. Discord 인텐트의 포털 설정→플래그 활성화 순서와 감시 꺼짐 상태를 확인해야 한다. 사용자에 의한 외부 인원 허용은 명시적 확인 절차를 유지한다.

## 완료한 UI-UX 개선

- `/help/integrations`에 OAuth, 앱·저장소·팀, 이슈 동기화, GitHub 부분 성공, Discord 알림·DM의 해결 절차와 주제별 질문 복사를 제공한다. 실패 진단에는 단계·상태·대상·시각만 기록한다. OAuth code/state와 토큰·개인키·외부 API 오류 원문은 복사 질문에서 제외한다.
- OAuth 상태 만료/불일치와 코드·인증 실패를 안내한다. 계정 연결 성공과 초기 저장소 조회 실패를 분리하며 재조회할 수 있다.
- 저장소 후보의 앱 미설치, 조회 실패, 정상 빈 목록을 구분한다. 기존 직접 주소 입력은 유지한다.
- 이슈 동기화 실패의 해결 경로와 조직 부분 성공의 실패 저장소를 표시한다. 기존 PM 태스크는 재생성하지 않는다.
- GitHub 조직 초대·제거, 팀 이름·설명, 팀 멤버 추가·제거, 일괄 추가의 실패 항목을 현재 로그인 세션에서 최대 20개 보관한다. 도움말에서 **GitHub만 다시 반영**할 수 있다. 실행 때 로그인·POST·CSRF·조직 관리자·현재 설치/팀/계정/PM 상태를 확인한다. 오래된 의도는 취소한다. 토큰을 보관하지 않고 실행자의 현재 사용자 토큰으로 호출한다.
- GitHub 팀 ID로 변경된 slug를 다시 찾고, 기존 active/pending 팀 멤버십은 역할을 덮어쓰지 않는다. 새 팀/이슈/브랜치 생성은 중복 위험 때문에 자동 재시도 목록에 넣지 않는다. GitHub 실제 상태 확인 후 복구하도록 안내한다.
- Discord 도움말 내용은 공통 페이지에 준비했다. `orgs/discord.html`의 링크 추가는 담당 세션의 화면과 통합할 때 한다.

재시도는 세션 범위이며 로그아웃/세션 만료 후 보존되는 영구 작업 큐가 아니다. 이 한계와 수동 복구 절차를 화면에 설명했다. 로그인 서버의 실제 GitHub/Discord 권한 및 전달 결과는 검증하지 않았다.

## Discord 확장 제안의 조정

담당 세션의 비공개·접근 감시가 먼저 기반을 만든다. 제안은 아래처럼 순서를 맞춘다.

1. **현재 담당 범위:** 팀·프로젝트 연결 현황, 권한 밖 인원 경고, 명시적 허용·철회, 새 인원 재경고, 감시 꺼짐/확인 불가 표시. Discord에서 생성·연결하는 현재 계획을 유지한다.
2. **통합 후 확장 후보:** 웹에서 생성·연결 작업을 시작하는 흐름. 기존 bridge를 재사용하되 담당 세션의 실행자 권한 확인·연결 전 접근 검증·허용 명단 규칙을 그대로 사용한다. 이를 별도 구현하려면 현재 “웹에서 고르지 않음” 설계 변경으로 검토한다.
3. **추가 후보:** 조직 알림 채널 웹 선택, 대상별 알림 수신 상태, 팀원 변동 시 Discord 미접근 인원 안내와 복구 경로. 팀원 자동 권한 반영은 현재 계획에서 제외돼 있으므로 이미 구현되는 것으로 설명하지 않는다.
4. **생성 후 실패 복구:** Discord 생성 성공과 PM 연결 저장 실패를 구분하고 남은 채널을 확인할 수 있게 한다. 연결 해제와 채널 삭제를 별도 작업으로 둔다.

근거: 상대 워크트리 `docs/IMPL-PLAN-5.md` B1–B9. 이 제안은 상대 세션의 기능 확정이나 권한 설정 승인을 대체하지 않는다.
