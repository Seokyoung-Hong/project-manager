## 0. 결론 요약

- **추천: 부분 이전.** 업무 관리 3종 DB(Team Members·Projects·Tasks)와 회의록은 유달리로, 위키성 문서(가이드·Ground Rule·변천사·온보딩 자료·정보처 메모·신기능 투표)와 프로젝트 내부 기술 문서는 당분간 Notion에 남기고 유달리에서 링크로 연결합니다.
- 근거
  - 유달리의 프로젝트 상태 8종은 Notion 가이드의 상태 체계를 그대로 옮긴 것이며 `정지`·`지원 종료`까지 갖췄습니다(`docs/SPEC-FUNCTIONAL.md:114-126`, N:산돌이 프로젝트 Notion 업무 시스템 사용 가이드 "상태(Status) 체계").
  - Notion의 롤업·수식(업무 수·진행 중·완료·중요 업무)과 "완료 버튼으로 완료일시 기록"은 유달리가 기본 기능으로 갖고 있습니다(프로젝트 집계 `docs/SPEC-FUNCTIONAL.md:156`, 부하 현황 `:434-440`, `Task.completed_at` `core/tasks/models.py:46`).
  - 데이터 규모가 작습니다: Team Members 9행, Projects 15행, Tasks 약 46행, 문서 정리 약 27행(아래 1절). 수작업이나 간단한 가져오기 명령으로 하루 안에 끝낼 수 있습니다.
  - Notion 현황판이 실제와 어긋나 있다는 팀 내부 진단이 있습니다(N:산돌이 신규 백엔드·DevOps 온보딩 분석 (2026-08-07) §4-3 "현재 현황판은 반드시 정리해야 함"). 그래서 이전과 정리를 함께 하기 좋은 시점입니다.
  - 팀이 이미 새 워크스페이스로 옮길 계획이었습니다(N:산돌이 시즌 3 시작 회의 §1-3 "새 워크스페이스 생성·기존 내용 복제", 문제는 "워크스페이스 권한 이양").
- 막히는 지점: 담당자 여러 명인 태스크, 프로젝트 여러 개에 걸친 태스크, 태스크 안의 개발일지 DB, 중첩 위키 페이지. 유달리는 태스크마다 담당자 1명·프로젝트 1개만 받습니다(`docs/SPEC-FUNCTIONAL.md:89`, `core/tasks/models.py:26,32`).

## 5. 확인 불가

- 각 Task 행의 개발일지 DB 내용: Auth Relay 서버 개발 1건만 열어 0건 확인. 나머지 약 45건은 열지 않음.
- Projects 15행 중 내부 API·설계 문서가 실제로 채워진 행 수: Auth Relay 1건만 확인.
- 페이지 댓글·멘션 사용량: 회의록 2건에서 0건 확인, 나머지 미확인.
- Tasks 정확한 행 수: 가상 스크롤로 "약 46"까지만 셈(텍스트 33건 + 스크롤 화면 13건).
- Tasks의 피드·타임라인·캘린더 보기의 실제 사용 빈도.
- "파트별·담당자별 프로젝트" 보기의 형식(보드로 추정, 열지 않음).
- 유달리에서 같은 GitHub 저장소를 두 프로젝트에 연결할 수 있는지(`core/github/models.py:47-52`에 고유 제약이 보이지 않으나 서비스 검증은 확인 안 함).
- 유달리 조직 전체 태스크 달력·활동 피드 존재 여부.
- Notion 내보내기(Markdown & CSV)는 실행하지 않았음(읽기 전용 지시). 변환 품질은 실제 내보내기 후 확인 필요.
