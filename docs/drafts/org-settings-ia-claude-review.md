# 조직 설정 IA — Claude의 Sol 안 검토

대상: `docs/drafts/org-settings-ia-sol.md`(Sol), 비교: `docs/drafts/org-settings-ia-claude.md`(Claude). 기준: 지시서 `org-settings-ia-brief.md` 요구 1~5(5는 정정판). 코드 수정 없음.

## 0. 추가 요구 5(정정판) 준수 여부 — Sol 안은 맞다

- 실명 = 계정 공통(`core/accounts/models.py:17`), `OrgMembership.real_name`은 읽지 않는 옛 열(`core/orgs/models.py:78-80`). Sol §1·§2.2·§4가 이를 정확히 적었다.
- 관리자 편집 대상 = 조직 표시 이름·구성원 정보 값(+기술 태그). 실명·계정 표시 이름·아이디 입력칸 없음, 관리자 요청에 실명 필드가 오면 거절(Sol §3 흐름 2, §6 권한 첫 줄). **정정판과 일치.**
- 본인이 내 정보 탭에서 계정 실명을 고칠 수 있게 한 것은 정정판이 금지하지 않는다(금지 대상은 관리자 수정). 아래 §3-1에서 받아들인다.

## 1. 동의하는 점

1. 설정을 모든 구성원에게 열고 기본 탭 = 내 정보, 구성원 관리는 관리자 탭(요구 2). 두 안이 같다.
2. 실명 표시 켬 → 조직 표시 이름 칸을 본인·관리자 모두 **렌더하지 않고 서버도 거절**, 값은 보존(요구 3, `orgs/names.py` 규칙). 같다.
3. 이름 표시 방식과 구성원 정보 항목 정의를 독립 섹션·독립 제목으로 분리(요구 1, `settings.html:31-39`의 결합 폼 해체). 같다.
4. 항목 정의 = "질문을 만드는 곳", 구성원 패널 = "답을 고치는 곳"이라는 첫 설명 문장(Sol §5). Claude 안보다 명확하다.
5. 관리자 대리 수정 이력에 **값 없이 항목 이름·수정자·시각만** 남김. 같다.
6. 관리자 수정으로 필수 값이 채워지면 그 구성원의 조직 관문 해제. 같다.
7. 전사: 서버·정책 7개만 설정으로, 전사 작업 목록은 업무 메뉴에 유지. 이슈·회의록·업무 규칙 문서도 메뉴 유지. 같다.
8. 84개 매핑: `task.doing_limit*` 2개를 빼면 탭 배치가 사실상 같다(태스크·프로젝트 / 알림 / AI / 회의·전사 / 저장 공간).

## 2. 반대하는 점과 근거

| # | Sol 안 | 반대 이유·근거 | 제안 |
|---|---|---|---|
| 1 | 일반 구성원에게 **"업무 규칙" 탭 읽기 공개** + 알림·회의 정책 요약 동봉(Sol §1:24, §7) | 조직 메뉴 "업무 규칙"(`orgs/governance.html:5-15`)이 이미 `enforced_rows`로 "현재 적용 중인 설정"을 구성원에게 보여 준다. 같은 정보가 두 곳이 되고, Sol 스스로 옛 메뉴를 "업무 규칙 문서"로 개명해야 할 만큼 이름이 충돌한다. 요구 2는 구성원 탭으로 "내 정보"만 요구 | 구성원은 내 정보만. 관리자 탭 이름은 "태스크·프로젝트". 구성원이 보는 적용 규칙은 governance 화면이 계속 맡음 |

| 4 | 대리 수정 **즉시 통지를 필수**, 전달 기록 별도 저장(Sol §3) | Sol도 "통지 수단 존재 미확인·구현 조사 범위"라고 적었다. 새 알림 종류·전달 기록 모델은 범위를 키운다 | 1차: 이력 + 내 정보 "관리자가 바꾼 기록" + 다음 접속 한 줄 안내. Discord DM은 `user.notify_dm`을 따르는 한 줄로 2차 |
| 5 | 폼 연 사이 다른 사람 수정 시 **충돌 감지 후 재확인**(Sol §3 흐름 4) | 구성원 한 명의 조직 정보를 관리자와 본인이 동시에 고칠 일은 드물다. 버전 필드·충돌 화면이 새로 필요 | 마지막 저장 우선. 이력으로 추적 |

## 3. Sol 쪽이 더 나아서 Claude 안을 바꾸는 점

1. **내 정보에서 본인 계정 실명 편집 허용**(라벨 "실명(계정 공통)" + "모든 조직에 반영, 관리자는 수정 불가" 안내). Claude 안은 읽기 전용 + 프로필 링크였는데, 요구 2("이 조직용 실명…모두 설정, 별도 페이지로 넘어가지 않는다")를 더 잘 충족한다. 저장은 기존 `clean_real_name` 재사용, 대상은 항상 로그인한 본인.
2. **GitHub·Discord를 "연동" 한 탭으로**(섹션은 `github_enabled`·`discord_enabled`에 따라 표시). 관리자 탭 수가 줄어든다.
3. **"내 GitHub 연결" 카드는 계정 설정 → 프로필로**(`orgs/github.html:57-66`). 개인 계정 연결이라 조직 관리 탭에 두면 안 된다. Claude 안이 놓쳤다.
4. **URL은 `?tab=`·`&member=` 쿼리**. 뷰·URL 이름이 `org_settings` 하나로 남아 `_OPEN_VIEWS`(`common/middleware.py:48-51`)를 고치지 않아도 되고, `member_info.url()`도 `reverse("org_settings")+"?tab=me"` 한 줄이다. Claude 안의 하위 경로보다 변경이 적다.
5. **옛 `member-info` POST 호환**(303으로 본문을 버리지 않음). Claude 안은 GET 301만 다뤘다.
6. **탭별 저장 시 다른 탭 값 소실 위험 지적.** 코드 확인: `set_org_settings`는 설정을 **통째로 교체**하고(`core/orgs/services.py:88-97`), `set_locks`도 잠금 목록 전체를 교체한다(`:122-129`). 지금 뷰는 전사 7개만 보존해 합친다(`core/web/views/orgs.py:600-603`). 탭별 저장이면 뷰가 "이 탭 밖의 키·잠금은 기존값 유지"로 합쳐야 한다. `set_definition`(`member_info.py:78`)도 표시 정책·항목을 함께 받으므로, 폼을 나누면 다른 쪽은 기존값을 넘겨야 한다. Claude 안 §8에 빠졌던 필수 구현 항목이다.
7. 구성원 미완료·초과 수는 "사람별 할 일 양"으로 넘기고 구성원 목록에서는 뺀다(목록을 신원·역할 중심으로 가볍게).
8. 항목 정의 제약값(항목 30개·이름 50자·선택지 50자×30개)을 형식 설명에 표시한다.

## 4. 합칠 때의 최종 제안

### 4.1 탭 목록·권한

| 순서 | 탭(`?tab=`) | 보는 사람 | 섹션 |
|---|---|---|---|
| 1 | 내 정보 `me`(기본) | 모든 구성원 | 이 조직에서 보이는 이름(미리보기) → 실명(계정 공통, 본인 편집)·조직 표시 이름(실명 표시 켬이면 없음) → 구성원 정보 → 관리자가 바꾼 기록 → 개인 환경설정 링크 |
| 2 | 구성원 관리 `members` | 관리자 | 구성원 목록(+`&member=` 패널) → 가입 전 구성원·초대 링크(+`org.invite_*`) → 이름 표시 방식 → 구성원 정보 항목 → 팀·스킬 태그 정책(`org.team_join_self`, `org.tags_by`) |
| 3 | 태스크·프로젝트 `work` | 관리자 | 만들기·기한 → 진행·검토(`doing_limit*` 포함) → 변경 사유 → 프로젝트 권한 → 프로젝트 기본값 |
| 4 | 알림 `notify` | 관리자 | 기한 알림 → 막힘·검토 알림 → 주간 보고 → 채널 게시·GitHub 알림 |
| 5 | 회의·전사 `meeting` | 관리자 | 녹음 → 공개·보관 → 전사 용어 → 전사 이용 정책 → 전사 서버(+시험·적용) |
| 6 | AI `ai` | 관리자 | AI 자동완성 사용·권한 → 조직 AI 연결·한도(+시험) → AI 쓰기 권한(태스크 / 조직·요청) |
| 7 | 연동 `integrations` | 관리자, 연동 켜진 것만 | Discord 서버·채널·알림 채널 → GitHub 앱·권한 점검·저장소 현황 |
| 8 | 조직 관리 `organization` | 관리자 | 저장 공간 → 설정 변경 이력 → 위험 구역 |

- 구성원이 관리자 탭을 쿼리로 요청하면 서버가 내 정보로 돌려보낸다(데이터를 내보내지 않음).
- 조직 메뉴: 개요·팀·사람별 할 일 양·로드맵·업무 규칙(이름 유지)·문서·회의록·전사(작업만)·이슈·설정(모두). 구성원 정보·GitHub·Discord 탭 삭제.

### 4.3 사용자에게 물을 것(판단이 남은 것)

1. 구성원에게 설정 안 "업무 규칙" 읽기 탭도 보일지(Claude: 아니오 / Sol: 예).
2. 관리자 대리 수정 시 Discord DM을 1차에 넣을지.
3. `task.doing_limit`를 사람 규칙(구성원 관리)과 태스크 전환 규칙 중 어느 쪽으로 볼지.
