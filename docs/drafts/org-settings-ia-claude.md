## 0. 확인한 사실(설계 전제)

- **실명은 계정 공통이다.** `User.real_name`(`accounts/models.py:17`) 하나. `OrgMembership.real_name`(`orgs/models.py:80`)은
  orgs 0014에서 계정으로 옮긴 뒤 "되돌리기용으로만 남긴다 — 읽지 않는다" 주석이 붙은 죽은 열이다(0015에서 삭제 예정).
  → 관리자는 실명을 **볼 수만** 있고 고칠 수 없다(추가 요구 5 정정). 구성원 본인도 조직 화면이 아니라 개인 설정 → 프로필에서 고친다.
- **조직 한정 정보**는 둘뿐이다: `OrgMembership.nickname`(조직 표시 이름, `:77`), `OrgMembership.info`(구성원 정보 항목 값, `:82`).
  여기에 관리자가 조직 안에서 붙이는 값(역할 `role`, 스킬 태그 `tags`, 팀 소속)이 있다 — 구성원이 제공한 정보는 아니지만 조직 한정이다.
- 표시 규칙(`orgs/names.py`): 실명으로 표시 켬 + 실명 있음 → 실명, 아니면 nickname, 아니면 계정 표시 이름. 켜도 nickname 값은 지우지 않는다.
- 필수 구성원 정보가 비면 그 조직 화면이 막힌다(`MemberInfoGate`). 열린 화면: `org_member_info`, `org_settings`, `org_member_fields`, `member_nickname` 등(`middleware.py:48-51`).
- 조직 설정 화면은 지금도 **비관리자가 URL로 열면 읽기 전용**으로 보이지만(`views/orgs.py:596`), 메뉴 탭은 관리자에게만 보인다(`_tabs.html:16`).
- 84개 중 전사 서버 7개(`STT_KEYS`)는 조직 설정 화면에서 빠지고 조직 메뉴 "전사"의 서버 보기에서 저장한다(`views/orgs.py:597`).
- `user` 그룹 7개는 scope=user라 조직 설정에 나오지 않는다(개인 설정 → 환경설정).

## 1. 새 구조 개요

조직 메뉴의 "설정"을 **모든 구성원에게 보이게** 하고, 그 안을 디스코드 서버 설정처럼 **왼쪽 탭 목록 + 오른쪽 본문**으로 나눈다.
탭 목록은 두 묶음으로 머리글을 단다: "나"(모든 구성원) / "조직 관리"(관리자만, 비관리자에게는 묶음째 안 보임).

| 순서 | 탭 | URL | 누가 보나 | 섹션 순서 |
|---|---|---|---|---|
| — | **나** | | | |
| 1 | 내 정보 | `orgs/<id>/settings` (=`settings/me`) | 모든 구성원 | ① 이 조직에서 보이는 이름 ② 구성원 정보 ③ 관리자가 바꾼 기록 ④ 개인 알림·화면은 개인 설정에서(링크 한 줄) |
| — | **조직 관리** | | | |
| 2 | 구성원 관리 | `settings/members` | 관리자 | ① 구성원 목록 ② 가입 전 구성원 추가 ③ 초대 링크 ④ 이름 표시 방식 ⑤ 구성원 정보 항목 ⑥ 팀·스킬 태그 정책 |
| 3 | 태스크·프로젝트 | `settings/work` | 관리자 | ① 만들기 기본값 ② 진행·검토 ③ 사유 필수 ④ 기한 ⑤ 프로젝트 권한 ⑥ 프로젝트 기본값 |
| 4 | 알림 | `settings/notify` | 관리자 | ① 기한 알림 ② 주간 보고 ③ 관리자 독촉 ④ 채널 게시 ⑤ GitHub 알림 |
| 5 | AI | `settings/ai` | 관리자 | ① AI 쓰기 권한(MCP·AI 도구) ② AI 자동완성 ③ 조직 AI 서버·한도(+연결 시험) |
| 6 | 회의·전사 | `settings/meeting` | 관리자 | ① 녹음 ② 회의록 ③ 전사 수단·권한 ④ 전사 서버(+연결 시험·적용) |
| 7 | GitHub | `settings/github` | 관리자, `github_enabled`일 때 | 지금 `orgs/github.html` 섹션 그대로(설치 상태 → 앱 권한·이벤트 점검 → 내 GitHub 연결 → 저장소 연결 현황) |
| 8 | Discord | `settings/discord` | 관리자, `discord_enabled`일 때 | 지금 `orgs/discord.html` 그대로(Discord 서버 → 팀·프로젝트 채널 → 알림 채널) |
| 9 | 일반 | `settings/general` | 관리자 | ① 저장 공간(첨부 용량) ② 설정 변경 이력 ③ 위험 구역 |

- 탭마다 **폼 하나·저장 버튼 하나**. 지금처럼 84개를 한 폼으로 일괄 저장하지 않는다(저장 범위가 눈에 보이게). 저장 뒤 같은 탭 URL로 돌아온다(열린 섹션·스크롤 유지 수정 `3e2a7d8` 그대로 적용).
- "AI의 변경 요청 N건"(`_pending_requests.html`)과 "조직 기본값과 잠금" 안내는 규칙 탭(3~6) 맨 위에만 둔다. 내 정보·구성원 관리에는 해당 없음.
- 탭 이름을 "업무 규칙"이 아니라 **"태스크·프로젝트"**로 한 것은 조직 메뉴에 이미 "업무 규칙"(`org_governance`, 규칙 문서 + 현재 적용 설정 읽기 전용)이 있어서다.

조직 메뉴(`orgs/_tabs.html`)는 이렇게 줄어든다:
개요 · 팀 · 사람별 할 일 양 · 로드맵 · 업무 규칙 · 문서 · 회의록 · 전사 · 이슈 · **설정(모두)**.
"구성원 정보"·"GitHub"·"Discord" 탭은 없어지고 설정 안으로 들어간다. 전사 탭은 작업 목록 보기만 남는다.

## 3. "구성원 관리" 그룹

| 섹션 | 들어갈 것 | 이유 |
|---|---|---|
| ① 구성원 목록 | 이름·역할·팀·정보 상태 배지(입력 필요)·Discord·미완료 / 행을 누르면 구성원 패널 | 사람 단위 작업의 입구. 디스코드 "멤버" 목록 |
| ② 가입 전 구성원 추가 | 표시 이름 입력 + 추가 | 사람을 늘리는 일 |
| ③ 초대 링크 | 링크 표·만들기·폐기, `org.invite_days`, `org.invite_max_uses` | 초대 정책을 실제 링크 옆에서 |
| ④ 이름 표시 방식 | 라디오 두 개: "구성원이 정한 조직 표시 이름"(기본) / "실명" + 이름 미리보기 | 실명 표시 옵션을 항목 정의와 분리(요구 1) |
| ⑤ 구성원 정보 항목 | 항목 정의(§5) | 구성원이 조직에 제공할 정보의 틀 |
| ⑥ 팀·스킬 태그 정책 | `org.team_join_self`, `org.tags_by` | 구성원이 스스로 무엇을 바꿀 수 있나 |

옮기지 않은 후보와 이유:
- `meeting.member_pc`·`meeting.transcribe_level`: "누가"를 정하지만 전사 서버값과 함께 봐야 뜻이 통한다 → 회의·전사.
- `assist.org_level`·`assist.org_daily_limit`: 같은 이유 → AI.
- `project.*_by`: 사람이 아니라 프로젝트 권한 → 태스크·프로젝트.

|---|---|---|
| 머리 | 이 조직에서 보이는 이름(큰 글씨) · 계정 표시 이름 · 아이디 · 가입 전 배지 | — |
| 계정 공통(회색 상자) | 실명(미입력이면 "실명 미입력" 배지) | **불가**. 설명 "실명·계정 표시 이름은 여러 조직에 공통인 계정 정보라 본인만 바꿀 수 있습니다" |
| 이 조직에 제공한 정보 | 조직 표시 이름, 구성원 정보 항목 값 전부(형식대로 입력칸) | **가능** — 한 폼, [저장] |
| 조직 안 역할 | 역할(관리자/멤버), 소속 팀, 스킬 태그 | 가능(역할·태그는 기존 엔드포인트 재사용) |
| 초대·제거 | 가입 전이면 개인 초대 링크 / 조직에서 제거 | 기존 동작 |

- **실명으로 표시가 켜진 조직**: 조직 표시 이름 칸을 그리지 않는다. 대신 한 줄 "이 조직은 실명으로 표시합니다 — 표시 이름: 실명(홍길동)". 저장값 `nickname`은 지우지 않는다(옵션을 끄면 되살아남, IMPL-PLAN-13 규칙). 서비스 `set_nickname`이 이미 실명 표시 조직을 거절한다.
- **필수 항목 검사**: 관리자 저장은 형식·길이·선택지 검사만 하고 필수 비움은 막지 않는다(본인이 아직 안 낸 다른 항목 때문에 한 칸 정정을 못 하면 안 되므로). 관리자가 필수를 다 채우면 그 구성원의 관문이 풀린다 — 저장 후 "이제 이 구성원은 조직을 쓸 수 있습니다" 안내.
  → `member_info.save(m, values, actor)`에 `enforce_required = (actor == m.user)` 하나만 추가하면 된다.
- **변경 이력**: `ChangeLog(target_type="org", field="nickname"|"member_info")`, `source="web"`, actor=관리자. 조직 표시 이름은 전후 값을 남긴다(지금 `set_nickname`과 같음). 구성원 정보 값은 **항목 이름만** 남기고 값은 남기지 않는다(연락처 등 개인정보가 이력 표에 쌓이지 않게).
- **본인에게 알림**: 새 알림 채널을 만들지 않는다. ① 본인의 내 정보 / ③ "관리자가 바꾼 기록"에 최근 변경(누가·언제·어느 항목)을 그린다(위 ChangeLog를 그 구성원 행 기준으로 읽기). ② 다음 접속 때 조직 화면 상단 한 줄 안내 "관리자 ○○님이 이 조직의 내 정보를 수정했습니다 [확인]"(본 시점은 `OrgMembership`에 날짜 하나 또는 세션). Discord DM은 보내지 않는다 — 갈릴 지점 §7-5.
- **계정 공통 정보 보호**: 패널 폼에는 `nickname`, `v-<항목 id>`만 받는다. 실명·계정 표시 이름 입력칸이 구조적으로 없고, 뷰는 그 키가 와도 무시한다(시험 하나: 관리자 POST에 `real_name`을 넣어도 `User.real_name` 불변).

## 4. "내 정보" 탭

`orgs/<id>/settings`의 기본 탭. 모든 구성원(관리자 포함). 한 화면 안에서 고치고 저장 후 같은 탭으로 돌아온다 — 다른 페이지로 가지 않는다.

```
[내 정보]
① 이 조직에서 보이는 이름
   미리보기: "이 조직에서는  ( 석영 )  으로 보입니다"
   ─ 실명으로 표시 꺼짐 ─
   조직 표시 이름 [ 석영        ]  (비우면 계정 표시 이름 'tjrdu'로 보입니다)
   실명  홍석영 · 관리자만 봅니다 · 프로필에서 변경 ↗
   ─ 실명으로 표시 켜짐 ─
   (조직 표시 이름 칸 없음)
   이 조직은 구성원 이름을 실명으로 표시합니다.  홍석영 · 프로필에서 변경 ↗
② 구성원 정보  ({{조직}}이 정한 항목, 조직 관리자가 열람)
   학번 (필수) [        ]  도움말
   소속 학과 (필수) [선택 ▾]
   ...
   [내 정보 저장]   ← ①의 표시 이름과 ②를 한 번에 저장
③ 관리자가 바꾼 기록(있을 때만, 최근 5건)
④ 알림 시각·첫 화면 같은 개인 환경설정은 개인 설정 → 환경설정 ↗
```

- **요구 3**: 실명으로 표시가 켜지면 ①의 조직 표시 이름 입력칸 자체를 렌더하지 않는다(숨김 속성이 아니라 미출력, 서버도 거절).
- 실명은 이 탭에서 고치지 않는다(계정 공통). 요구 2의 "이 조직용 실명"은 **"이 조직에서 실명이 어떻게 쓰이는지 보이고, 고치는 길을 바로 연결"**로 해석했다 — §7-1.
- **저장**: 폼 하나(`nickname` + `v-*`). 서버는 `set_nickname` → `member_info.save` 순으로 한 트랜잭션. 오류는 칸 옆에 표시하고 같은 탭을 다시 그린다. 성공 시 `redirect(settings/me)`. 관문 걸린 상태에서 필수가 채워지면 원래 가려던 화면(`next`)으로 보낸다(지금은 개요로 감).
- **필수 미입력 관문과의 관계**: `MemberInfoGate`가 보내는 곳을 `settings/me`로 바꾼다(`member_info.url()` 한 곳만 바뀌면 웹·API 403 메시지·`X-Blocked-Orgs`가 함께 바뀜). 관문 상태에서는 탭 목록에 "내 정보"만 활성, 상단 경고 "필수 항목을 입력해야 ○○ 조직을 쓸 수 있습니다". 관리자도 필수를 비우면 같은 관문이지만 조직 관리 탭은 열린다(항목 정의를 고칠 수 있어야 하므로 — 지금 `_OPEN_VIEWS`에 `org_settings`가 있는 것과 같은 이유).
- 항목이 없는 조직: ② 대신 "이 조직은 구성원 정보를 받지 않습니다." 한 줄.

## 5. 구성원 정보 항목 정의를 이해되게

지금 문제: 7열 표(순서·이름·형식·필수·도움말·선택지·삭제) + 빈 줄이 "새 항목", 실명 체크와 한 폼. 무엇을 채우면 구성원 화면에 어떻게 나오는지 보이지 않는다.

바꾸는 안(구성원 관리 / ⑤):

1. **두 단 배치**: 왼쪽 "항목 편집" / 오른쪽 "구성원에게 보이는 모습" 실시간 미리보기(내 정보 ② 폼을 그대로 그림, 입력 불가). 850px 이하에서는 미리보기가 편집 아래로 내려가고 [미리보기] 접기.
2. **항목 = 카드 한 장**(표 행 대신):
   - 항목 이름 / 도움말(입력칸 아래 회색 글로 보임 — 카드 안에 그 위치를 그대로 표시)
   - 형식: 세그먼트 3개, 각 선택지에 한 줄 설명
     - 짧은 글 — 한 줄 입력, 200자. 예: 학번, 연락처
     - 긴 글 — 여러 줄, 2000자. 예: 자기소개, 가능한 시간
     - 선택지 — 목록에서 하나 고름. 이때만 "선택지(한 줄에 하나)" 칸이 나타난다
   - 필수 스위치 + 결과 문장: "켜면 이 항목을 비운 구성원(관리자 포함)은 입력할 때까지 이 조직을 쓸 수 없습니다"
   - ↑ ↓ 순서 버튼, [항목 삭제](삭제 시 "입력된 값은 더 이상 보이지 않습니다" 확인)
3. **[+ 항목 추가]** 버튼(빈 줄 방식 폐지). 항목이 0개일 때는 예시 칩 "학번 · 소속 학과(선택지) · 연락 가능한 시간(긴 글)" — 누르면 채워진 카드가 생긴다(저장 전까지 확정 아님).
4. **저장 전 영향 안내**: 필수 항목을 새로 만들거나 필수로 바꾸면 저장 확인에 "지금 N명이 이 항목을 비워 두고 있어 저장하면 입력 전까지 조직을 쓸 수 없습니다"(N은 서버 계산, `blocked_user_ids`와 같은 방식).
5. **관리자 쪽 결과도 한 줄**: "입력값은 구성원 관리 → 구성원 목록의 '정보' 열과 각 구성원 패널에서 봅니다."
6. 이름 표시 방식(④)은 다른 카드·다른 저장 버튼. ④에도 미리보기 "목록·담당자 칸에 이렇게 보입니다: 홍석영 / 석영".
7. 민감정보 금지 경고(약관 제6조)는 ⑤ 머리에 그대로.

저장 데이터 모양(`member_fields.fields`)은 바꾸지 않는다 — 화면만 바뀐다. 순서는 숨은 `order` 대신 카드 순서로 보낸다.

## 6. 권한 경계·URL·모바일

### 6.1 권한

| 탭 | 관리자 | 구성원 | 관문 걸린 구성원 |
|---|---|---|---|
| 내 정보 | 본인 것 편집 | 본인 것 편집 | 편집(유일하게 열림) |
| 조직 관리 2~9 | 편집 | **탭 목록에 없음**, URL 직접 접근은 403이 아니라 내 정보로 리다이렉트 + 안내 | 내 정보로 |
| 구성원 패널 | 모든 구성원의 조직 한정 정보 편집, 실명 열람 | 없음 | — |

- 구성원이 "왜 진행 중으로 못 바꾸지"의 답(현재 적용 규칙)은 조직 메뉴 **업무 규칙** 화면의 "현재 적용 중인 설정"이 맡는다(이미 있음). 그래서 설정 안에 읽기 전용 규칙 탭을 두지 않는다 — §7-3.
- 실명 열람은 구성원 패널·구성원 목록(관리자)뿐(IMPL-PLAN-13 §6.2 그대로). 구성원 응답에 남의 실명 문자열이 없어야 한다는 기존 시험 유지.

### 6.2 URL·리다이렉트

| 옛 주소 | 처리 |
|---|---|
| `orgs/<id>/member-info` (`org_member_info`) | `settings/me`로 301. URL 이름 `org_member_info`는 새 뷰로 옮겨 `member_info.url()`·API 메시지·`X-Blocked-Orgs`가 자동으로 새 주소를 낸다. 이미 보낸 Discord DM·API 응답 속 옛 링크는 301로 산다 |
| `orgs/<id>/member-fields` (POST) | `settings/members/fields`로 이동. 옛 경로는 307(POST 유지) 한 판 동안 |
| `orgs/<id>/settings` | 내 정보(기본 탭). 옛 `#member-info` 앵커 → JS 없이 서버가 처리 못 하므로 `settings/members#fields`로 가는 안내 링크를 내 정보에 관리자만 한 줄 |
| `orgs/<id>/settings#settings-group-N` | 그룹→탭 매핑으로 무시(앵커는 서버에 안 옴). 문서·스킬 속 링크는 grep으로 갱신 |
| `orgs/<id>/github`, `orgs/<id>/discord` | `settings/github`, `settings/discord`로 301. 설치 콜백(`github_installed`, `discord_installed`)이 돌려보내는 곳도 새 주소 |
| `orgs/<id>/transcribe?view=server` | `settings/meeting#stt`로 301 |
| `orgs/<id>/teams`의 구성원 앵커·`teams.html`의 "조직 설정 → 구성원 정보" 링크 | `settings/members`로 문구·링크 교체 |
| `MemberInfoGate._OPEN_VIEWS` | `org_member_info`(=settings/me), 구성원 관리의 항목 정의 저장, 관리자 탭들. `member_nickname`은 내 정보 폼으로 흡수되면 제거 가능 |

### 6.3 모바일(DESIGN.md §3.1·§9)

- ≥1101px: 왼쪽 탭 목록 220px(설정 목차 자리를 탭 목록이 씀). 탭 안 섹션이 4개 이상이면 본문 위에 섹션 칩 줄.
- ≤1100px: 탭 목록이 본문 위 가로 칩 줄(오른쪽 흐림으로 더 있음 표시). "나 / 조직 관리" 머리글은 칩 사이 구분선.
- ≤850px: 설정 행 세로 카드(기존). 구성원 정보 항목 미리보기는 편집 아래로.
- ≤700px: 구성원 목록 표 → 사람 카드 목록(이름·역할 배지·입력 필요 배지), 카드 탭 → 패널 전체 화면 + [← 구성원 목록]. 가로 스크롤 표를 없앤다. 터치 44px, 입력 16px.
- 내 정보는 원래 한 열 폼이라 그대로.

## 7. 판단이 갈릴 만한 지점과 선택

1. **"내 정보에서 이 조직용 실명을 설정"(요구 2) vs 실명은 계정 공통(코드·요구 5 정정)** — 실명 입력칸을 두지 않고 읽기 전용 + 프로필 링크. 조직별 실명을 되살리면 IMPL-PLAN-13 결정 #4(조직별 실명 폐지)와 처리방침 v5를 다시 바꿔야 한다.
2. **탭 = 하위 URL(서버 렌더) vs 한 페이지 안 JS 탭** — 하위 URL. 지금 코드가 서버 렌더·폼 POST·redirect 구조이고, 관문 리다이렉트·링크 공유·저장 후 복귀가 URL 단위라 단순하다. "별도 페이지로 넘어가지 않는다"는 **설정 화면(탭 목록) 밖으로 나가지 않는다**로 해석했다.
3. **구성원에게 규칙 탭을 읽기 전용으로 보일지** — 안 보인다. 읽기 전용 규칙은 업무 규칙 메뉴가 이미 맡고, 구성원 설정 화면은 디스코드처럼 "내 정보"만 있어야 덜 헷갈린다. 반대 의견: 지금은 URL로 읽기 전용 조회가 되던 것이 사라진다.
4. **구성원 목록을 팀 탭에서 설정으로 옮길지** — 옮긴다(팀 탭에는 팀만). 사람 관리 동선이 "설정 → 구성원 관리" 하나가 된다. 반대 의견: 구성원 목록은 자주 보는 업무 화면이라 메뉴 1단계에 있어야 한다.
5. **관리자 수정 시 본인 알림** — 내 정보 ③ 기록 + 다음 접속 한 줄 안내만, Discord DM 없음. 새 알림 종류·설정을 늘리지 않으려는 선택. 필요하면 `user.notify_dm`을 따르는 DM 한 줄을 나중에 붙인다.
6. **설정 변경 이력을 구성원에게 숨길지** — 일반 탭(관리자)으로 옮겨 숨긴다. 지금은 비관리자도 URL로 보였다.
7. **GitHub·Discord·전사 서버를 설정 안으로** — 넣는다(관리자 전용 연결 설정이라 메뉴 탭 수 12→10). 이슈·전사 작업 목록은 업무 화면이라 메뉴에 남긴다.
8. **한 폼 일괄 저장 → 탭별 저장** — 탭별. 저장 범위가 보이고, 실패 시 다른 탭 입력이 날아가지 않는다. 대신 탭 이동 시 저장 안 한 변경 경고(`beforeunload` 한 줄)가 필요.
9. **기본 탭** — 관리자도 내 정보. 관리자는 주로 규칙을 고치지만, 모두에게 같은 진입점이 관문·안내 링크를 단순하게 한다.
10. **관리자 저장 때 필수 항목 강제 안 함** — 한 칸 정정이 막히지 않게. 대신 관문은 계속 본인 기준으로 유지된다.
11. **구성원 정보 값 이력에 값을 남길지** — 항목 이름만. 개인정보 최소화. 분쟁 시 "무엇이 바뀌었는지"를 못 보는 비용이 있다.

## 8. 구현 범위 메모(참고)

- 새 뷰: `settings/<tab>`(탭별 렌더·저장), `settings/members/<mid>`(패널). 템플릿은 기존 `settings/_setting_row.html` 재사용, GitHub·Discord·전사 서버 템플릿은 include로 옮김.
- 서비스 변경은 작다: `member_info.save(..., actor)` 필수 검사 분기, 관리자 저장 ChangeLog, `member_info.url()` 대상. 모델 변경 없음(관리자 수정 알림 확인 시점을 DB에 둘 때만 필드 1개).
- 사용자 노출 문구(탭 이름·안내·확인창)는 Sol 문구 단계에서 확정. 용어는 IMPL-PLAN-13 §8(실명·표시 이름·조직 표시 이름·실명으로 표시·구성원 정보) 그대로.
