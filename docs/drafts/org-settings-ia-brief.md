# 조직 설정 정보 구조(IA) 재분류 — 공통 지시서

응답은 한국어로 한다. 로컬 python 직접 실행 금지(필요하면 `uv run`). 코드 수정·커밋 금지(분류안 문서만 작성).

## 목표
유달리 조직 화면의 설정·구성원 관련 항목을 다시 분류해 **조직 설정의 새 정보 구조(탭·섹션) 안**을 만든다. GPT(Sol)와 Claude가 각각 독립적으로 안을 만든 뒤 서로의 안을 검토해 합친다. 이 결과로 구현 범위를 정한다.

## 사용자 요구(확정)
1. 지금 조직 설정 맨 아래 "구성원 정보" 카드(실명 표시 체크 + 구성원 정보 항목 표)가 이해되지 않는다: 실명 표시 옵션과 구성원 정보 항목 정의가 구분되지 않고, **표에 무엇을 어떻게 채우면 어떻게 동작하는지** 모른다. → 별도 "구성원 정보/실명 표시" 덩어리가 아니라 **"구성원 관리" 옵션 그룹**으로 두고, 다른 설정 중 이 그룹으로 옮길 것도 찾는다.
2. **디스코드의 서버 프로필처럼**: 사용자가 조직 설정을 열면 **"내 정보" 탭**에서 이 조직용 실명·조직 표시 이름·관리자가 정한 구성원 정보 항목을 모두 설정한다. **별도 페이지로 넘어가지 않는다**(지금은 조직 메뉴의 "구성원 정보" 탭 `orgs/<id>/member-info`가 별도 페이지). 조직 설정은 지금 관리자만 보이는데, "내 정보" 탭은 모든 구성원이 봐야 한다 → 관리자 전용 탭과 구성원 공통 탭의 경계를 설계.
3. **실명 표시 옵션이 켜져 있으면 "이 조직 표시 이름" 입력은 나오면 안 된다**(실명이 표시되므로).
4. 설정 섹션을 저장해도 열린 섹션·스크롤이 유지돼야 한다(이건 이미 고침 — 참고만).

## 자료(저장소 C:\Users\tjrdu\orca\workspaces\project-manager\Ochestration)
- 설정 항목 전체 목록: `docs/drafts/settings-inventory.json`(84개: key·현재 group·scope(org/user/project)·label·help·overridable·hidden). 현재 그룹: task(태스크 규칙), project(프로젝트 권한), org(조직 운영), ai(AI 정책, MCP·AI 도구 권한), assist(AI 자동완성), notify(알림), meeting(회의 녹음), user(내 설정). 정의: `core/orgs/settings.py`(GROUPS 1086행 근처, SPECS).
- 조직 설정 화면: `core/web/templates/orgs/settings.html`(그룹별 접이식 섹션 + 구성원 정보 카드 + 변경 이력 + 위험 구역). 저장은 한 폼 일괄 저장.
- 조직 메뉴 탭: `core/web/templates/orgs/_tabs.html`(개요·팀·사람별 할 일 양·로드맵·업무 규칙·문서·회의록·전사·이슈·GitHub·Discord·구성원 정보·설정).
- 구성원 본인 입력 화면: `core/web/templates/orgs/member_info.html`, 뷰 `core/web/views/orgs.py`(org_member_info, org_member_fields), 서비스 `core/orgs/member_info.py`(필수 항목 미입력 시 조직 사용 차단 관문). 실명/조직 표시 이름: 계획서 `docs/IMPL-PLAN-13*`(있으면), accounts 모델.
- 구성원 목록·역할·초대·사람별 초대(가입 전 구성원) 등이 있는 화면도 찾아 넣는다(`grep -rn "invite\|role" core/web/templates/orgs`).
- 개인 계정 설정(`core/web/templates/settings/_tabs.html`)과 겹치는 것(예: user 그룹 '내 설정')의 경계도 본다.
- 디자인 규칙: 루트 `DESIGN.md`.

## 산출물(마크다운 파일)
- Sol: `docs/drafts/org-settings-ia-sol.md`, Claude: `docs/drafts/org-settings-ia-claude.md`
- 내용:
  1. 새 구조 개요: 조직 설정 안의 탭 목록(누가 보는지: 모든 구성원/관리자), 각 탭의 섹션 순서.
  2. **전체 매핑표**: settings-inventory.json의 84개 항목 + 구성원 정보 항목 정의 + 실명 표시 + 조직 표시 이름 + 구성원 목록·역할·초대 + 변경 이력·위험 구역 + 지금 조직 메뉴의 Discord·GitHub·전사 같은 관리 탭을 [현재 위치 → 새 위치(탭/섹션) → 이유]로. 빠짐 없이.
  3. "구성원 관리" 그룹에 들어갈 것과 이유.
  4. "내 정보" 탭 설계: 보이는 칸(실명·조직 표시 이름·구성원 정보 항목), 실명 표시 켜짐일 때 동작(표시 이름 칸 숨김 등), 필수 미입력 관문과의 관계, 저장 방식(별도 페이지 이동 없이).
  5. 구성원 정보 항목 정의 표를 이해되게 바꾸는 안: 무엇을 채우면 구성원 화면에 어떻게 보이는지(미리보기·예시 행·형식별 설명 등).
  6. 관리자 전용/공통 권한 경계, URL·리다이렉트(옛 `member-info` 주소 처리), 모바일.
  7. 판단이 갈릴 만한 지점과 당신의 선택 이유.
- 최종 답변(300단어 이내): 파일 경로, 핵심 구조 요약, 갈릴 만한 지점.

## 추가 요구(사용자, 진행 중 추가)
5. **조직 관리자는 구성원이 이 조직에 제공한 정보는 수정할 수 있고, 여러 조직에 공통인 계정 정보는 수정할 수 없다.** (사용자 정정)
   - 수정 가능(조직 한정, 구성원이 조직 운영자에게 직접 제공한 정보라는 개념): 조직 표시 이름, 관리자가 정한 구성원 정보 항목의 값.
   - 수정 불가(계정 공통): 로그인 ID, **실명**, 계정 표시 이름, 비밀번호, 다른 조직 정보 등.
   - "구성원 관리" 그룹 안에서 구성원별로 열어 조직 한정 정보를 고치는 흐름(디스코드 서버 멤버 관리처럼), 변경 이력·본인 알림 여부, 실명 표시 켜짐일 때의 동작(표시 이름 칸 숨김)을 설계에 넣는다. 실명이 지금 계정 공통인지 조직별인지 코드(accounts·orgs 모델, IMPL-PLAN-13)로 확인해 매핑에 적는다.
