## 1. 이번 라운드는 "수정"이다

지금까지의 지시서(`GUIDE-01`~`04`)는 **아무것도 없는 상태에서 만드는** 문서였다. 그 작업은 끝났다. core·discord_service·mcp_server가 동작하고 테스트 145개가 통과한다(커밋 `3b2fbee`).

이번 라운드는 **이미 있는 코드를 고친다.** 그래서 규칙이 다르다.

1. **지우고 새로 쓰지 않는다.** 파일을 통째로 갈아엎지 말고 필요한 곳만 고친다. 지시서에 파일 전체 코드가 있으면 그건 새로 만드는 파일이거나 거의 전부가 바뀌는 파일이다.
2. **테스트를 지우지 않는다.** 개명 때문에 깨지는 테스트는 이름만 고친다. 기대값을 바꿔 통과시키지 않는다. 기대값이 실제로 바뀌어야 한다면 지시서에 그렇게 적혀 있다.
3. **한 단계가 끝날 때마다 `pytest`가 전부 통과해야 한다.** 통과하지 않으면 다음 단계로 가지 않는다.
4. 새로 늘어나는 의존성은 `cryptography` **하나뿐**이고 `GUIDE-V2-07`에서 추가한다. 그 전 단계에서는 `pyproject.toml`을 건드리지 않는다.

## 3. 단계 공통 절차

각 단계에서 이 순서를 지킨다.

1. 그 단계의 지시서를 끝까지 읽는다.
2. 모델이 바뀌면 **마이그레이션을 먼저** 만들고 적용한다.
3. services → api → web → 템플릿 순서로 고친다. 업무 규칙은 언제나 `services.py`에만 둔다.
4. 테스트를 고치고 추가한다.
5. 검증을 실행한다.

```bash
cd core
uv run ruff format .
uv run ruff check .
uv run pytest -q
uv run python manage.py makemigrations --check --dry-run   # "No changes detected"여야 한다
```

Postgres에서도 한 번 돌린다(`db`만 띄운 상태에서).

```bash
cd core && DATABASE_URL=postgres://pm:pm@127.0.0.1:5432/pm uv run pytest -q
```

화면이 바뀐 단계는 목업과 나란히 놓고 본다.

```bash
python -m http.server 8765      # 저장소 루트. 유달리 신규 기능 목업.dc.html 을 연다
```

6. 커밋한다. 메시지 형식은 `feat: <단계 요약>` 또는 `refactor:`·`fix:`.
7. 완료 보고를 쓴다.

```
## V2-N 완료
- 바꾼 파일: ...
- 새로 만든 파일: ...
- 실행한 검증 명령과 결과: ...
- 지시서와 다르게 한 것: (없으면 "없음")
- 실패하거나 못 한 것: (없으면 "없음")
```

## 4. v1 범위

**v1 = 이 여덟 단계를 끝낸 상태.** 그러면 시범 운영에 투입할 수 있다.

넣지 않는 것은 지시서에 적혀 있지 않아도 만들지 않는다. 특히 다음은 **일부러 뺀 것**이므로 "있으면 좋을 것 같아서" 만들지 않는다.

- 팀에 저장소 권한 주기(읽기 전용 표와 GitHub 링크로만)
- PR 병합, PM에서 커밋, 저장소 생성·삭제, 브랜치 보호 규칙
- 개인에게 저장소 권한 직접 부여
- 배포 키, PAT 입력 화면
- 회의록 버전 이력 화면, 이미지 첨부
- 마일스톤에 태스크 연결, 로드맵 기간(분기·반기) 전환
- PR 리뷰 승인 수
- 부하 계산의 중요도 가중치
- 조직 초대 시 팀 자동 배정

## 5. 자주 틀리는 것

| 함정 | 바른 것 |
|---|---|
| `Team`이 두 뜻으로 보인다 | **개명 전 코드와 `GUIDE-01~04`의 `Team`은 조직이다.** 이번에 만드는 `Team`은 조직 안의 사람 묶음이고 완전히 다른 것이다. `GUIDE-V2-01`의 대조표를 옆에 두고 작업한다 |
| 팀으로 가시성을 자름 | **팀은 가시성을 제한하지 않는다.** 조직 멤버는 조직의 프로젝트·태스크를 전부 본다. 자르는 것은 GitHub에서 온 데이터뿐이다 |
| GitHub 설치 토큰으로 쓰기 | 설치 토큰은 **읽기 전용**이다. 모든 쓰기는 누른 사람의 사용자 토큰으로 나간다 |
| 회의록 렌더에 `innerHTML` | `createElement`·`textContent`만 쓴다. 이게 XSS를 막는 유일한 장치다 |
| `ArrayField` | Postgres 전용이라 SQLite 테스트가 깨진다. `JSONField(default=list)`를 쓴다 |
| `max_length` 초과 | `ChangeLog.source`는 4자(`gh`는 들어간다), `Link.kind`는 5자(`issue`·`dash` 모두 들어간다). 늘리지 않는다 |
| 뷰·라우터에 업무 규칙 | 검증·상태 전이·이력은 `services.py`에만 |
| 새 의존성 추가 | `cryptography` 하나뿐. 마크다운 라이브러리·HTTP 프레임워크·프런트엔드 패키지 모두 금지 |
| 숫자를 두 곳에서 계산 | 조직 개요·부하 현황·담당자별은 `reports.services.org_status()` **한 번의 호출**에서 나온다 |
