## 2. 비개발 팀(저장소 미연결) 프로젝트

### 2.1 현황
저장소 없이도 **깨지는 곳은 없다.** 상태 7단계·검토 대기·완료 조건·체크리스트·링크·문서·요청·Discord·MCP가 그대로 동작하고, GitHub 자동 규칙은 웹훅에서만 돈다.
문제는 세 가지다.
- 쓸모없는 화면: GitHub 탭·API 문서 탭이 늘 보임(projects/_tabs.html:8,10), 모든 태스크 패널에 "GitHub · 저장소 미연결" 블록(tasks/_panel.html:98).
- 개발 용어: 상태 설명, "개발 거버넌스", 링크 종류 "이슈", PR 안내 문구.
- 없는 기능: 반복 업무, 태스크 복제, 프로젝트 달력, 요청 희망 기한, 반려 사유.

### 2.2 구분 방식
새 모델 필드 대신 **설정 항목 `project.dev_tools`**(조직 기본값 + 프로젝트별 재정의)를 추가한다.
- 마이그레이션이 없고, 프로젝트 설정 화면·API·MCP에 코드 추가 없이 자동 노출된다(orgs/settings.py:737-741, 선례 `project.default_view`).
- 표시 규칙: `dev_tools 켜짐 또는 저장소 연결됨`이면 개발 화면을 보인다. 기본값은 켬이라 기존 프로젝트는 그대로다.
- 프로젝트 만들기 대화상자에 "개발 도구 사용" 체크박스(초기값 = 조직 설정).

### 2.3 권장 업무 흐름(비개발)
1. 접수: 다른 팀은 **요청**으로 일을 보낸다(희망 기한 포함).
2. 착수: 완료 조건 필수, 절차는 체크리스트로.
3. 산출물: 결과물 URL을 링크 종류 **"산출물"**로 붙인다(파일 업로드는 SPEC.md:29 결정대로 하지 않음).
4. 승인: 검토 대기로 올리면 프로젝트 관리자가 완료 처리(검토 필수·본인 검토 금지·독촉 2일을 권장 설정으로).
5. 반려: 검토 대기에서 되돌릴 때 사유를 남긴다.
6. 일정: 캠페인 주요 일자는 마일스톤, 개별 게시일은 태스크 기한.
