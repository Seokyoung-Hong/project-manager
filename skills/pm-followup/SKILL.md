# 후속 태스크 남기기

`../pm/SKILL.md`를 이 세션에서 읽지 않았다면 먼저 읽는다. 생성 규칙은 거기 "태스크 만들기"를 따른다.
작업 범위(조직·프로젝트)를 먼저 정하고 그 범위의 태스크만 다룬다(`../pm/SKILL.md` "작업 범위").

남길 일: $ARGUMENTS (비어 있으면 이 세션에서 "나중에", "범위 밖", "별도로" 처리하기로 한 일들을 모은다.)

## 흐름

1. **현재 태스크 찾기**: 이 세션에서 다룬 `TASK-N`(착수·브랜치 이름·커밋 메시지에서). 없으면 연결 없이 만든다.
2. **후보 정리**: 건마다 제목, 왜 생겼는지(무엇을 하다 발견했는지) 한 줄, 완료 조건, 관련 파일·위치.
   이미 이번 작업에서 고친 것, 막연한 느낌뿐인 것은 뺀다. 중복 검사는 공통 규칙대로.
3. **확인**: 표로 보여 주고 이슈 생성 여부(저장소가 연결됐을 때만)와 함께 한 번에 확인받는다.
   담당자는 기본값(나)으로 두고 바꿀지 묻는다. 기한이 정해지지 않았으면 `no_due_reason`을 `"후속 작업 — 일정 미정"`으로 제안한다.
4. **생성**: `POST /api/tasks` (`--key followup-<현재 id>-<순번>`). `description` 첫 줄에 `관련: TASK-N`(현재 태스크).
   이슈를 고른 건은 `POST /api/tasks/{id}/github/issue`.
5. **현재 태스크에 남기기**: 현재 태스크의 진행 메모 끝에 `후속: TASK-M 제목` 줄을 덧붙인다(GET → notes에 추가 → PATCH).
6. 보고한 뒤 원래 작업으로 돌아간다.
