# 이슈에서 태스크 만들기

`../pm/SKILL.md`를 이 세션에서 읽지 않았다면 먼저 읽는다.
작업 범위(조직·프로젝트)를 먼저 정하고 그 범위의 태스크만 다룬다(`../pm/SKILL.md` "작업 범위").

이슈: $ARGUMENTS

## 흐름

1. **프로젝트 정하기**: 현재 작업 폴더의 저장소(`git remote`)와 `GET /api/projects?org=` 각 프로젝트의
   `GET /api/projects/{id}/repo`를 맞춰 본다. 하나로 정해지지 않으면 묻는다. 저장소가 연결된 프로젝트가 없으면
   웹의 프로젝트 저장소 탭에서 연결해야 한다고 알리고 멈춘다.
2. **이슈 고르기**
   - 번호를 받았으면 그 번호들.
   - 없으면 `GET /api/projects/{id}/issues?imported=false`로 아직 가져오지 않은 열린 이슈를 번호·제목·라벨·담당과 함께
     보여 주고 고르게 한다. 목록은 동기화된 사본이다. 방금 만든 이슈가 없으면 웹에서 "새로 고침"을 하면 된다고 알린다.
3. **가져오기**: 고른 이슈마다 `POST /api/projects/{id}/issues/{number}/import`.
   201은 새 태스크(담당자 나, 기한 미정), 200은 이미 가져온 태스크다. 이미 있던 것은 그렇다고 알린다.
4. **채우기**: 새로 만든 태스크마다 이슈 본문을 읽고 완료 조건·다음 행동·체크리스트·기한 초안을 만들어
   표로 한 번에 확인받은 뒤 `PATCH`(최신 `version`)한다. 이슈에 없는 기한을 지어내지 않는다.
   이슈 하나가 여러 태스크 크기로 보이면 `/pm-split`을 제안한다.
5. **보고**: `#이슈 → TASK-N` 목록.
