# 태스크 만들기

`../pm/SKILL.md`를 이 세션에서 읽지 않았다면 먼저 읽는다. 절차의 기본은 거기 "태스크 만들기"다.

설명: $ARGUMENTS (비어 있으면 대화 내용에서 만들 일을 뽑는다. 뽑을 게 없으면 무엇을 만들지 묻는다.)

## 흐름

1. **초안**: 프로젝트, 제목, 완료 조건, 다음 행동, 체크리스트, 기한(또는 기한 미정 사유), 중요도, 담당자.
   프로젝트가 불분명하면 `GET /api/projects?org=`에서 후보를 골라 확인받는다.
2. **중복 확인**: 비슷한 열린 태스크가 있으면 보여 주고 "그걸 쓸지 / 새로 만들지"를 확인 질문에 넣는다.
3. **분할 판단**: 아래 중 하나라도 해당하면 분할 후보다.
   - 완료 조건이 따로 끝낼 수 있는 결과물 여러 개로 나뉜다
   - 필요한 담당자나 팀이 서로 다르다
   - 여러 프로젝트나 저장소에 걸친다
   - 체크리스트에 각각 별도 PR이 될 만한 덩어리가 있다
   - 거버넌스에 태스크 크기·기간 기준이 있고 그걸 넘는다

   후보면 **나누는 이유 한 줄과 분할안(제목·완료 조건·순서)**을 보여 주고 고르게 한다.
   - 나눠서 만들기 → `/pm-split`의 흐름으로 계속한다(표 확인, 건마다 `--key`).
   - 한 건으로 만들기 → 분할 단위를 체크리스트 항목으로 넣는다.

   후보가 아니면 묻지 않는다. **애매하면 묻지 않는다.**
4. **이슈 여부**: 저장소가 연결된 프로젝트면 (a) GitHub 이슈를 만들고 연결 / (b) 태스크만. 여러 건이면 전부 / 없음 / 골라서.
5. **한 번에 확인**: 초안, 중복 후보, 분할 제안, 이슈 여부를 한 질문으로 묶는다. 질문이 여러 번 오가지 않게 한다.
6. **생성**: `POST /api/tasks` (`--key new-<YYYYMMDD>-<짧은 요지>`), 이슈를 골랐으면 `POST /api/tasks/{id}/github/issue`.
7. **보고**: `TASK-N 제목` (+ 이슈 링크). 곧바로 시작할지 묻고, 원하면 `/pm-start TASK-N` 흐름으로 이어간다.
