# PR 설명 초안

`../pm/SKILL.md`를 이 세션에서 읽지 않았다면 먼저 읽는다.

대상: $ARGUMENTS (비어 있으면 현재 브랜치 이름·세션에서 `TASK-N`을 찾는다. 없으면 묻는다.)

## 흐름

1. `GET /api/tasks/{id}/pr-context` — 결정, AI 판단, 이슈·태스크 근거. `GET /api/tasks/{id}/github` — 이슈 번호와 저장소.
2. 작업 폴더가 그 저장소면 `git log`/`git diff <기본 브랜치>...HEAD --stat`으로 실제 변경을 확인한다.
   이 세션에서 실행한 테스트·검증만 결과로 쓴다.
3. 초안:

   ```
   제목: TASK-N <변경 요지>

   ## 무엇을·왜
   <사용자의 유효한 결정과 그 이유 중심>

   ## 결정
   - <요지> (사용자 확인 | 사용자 입력 | 제안 — 확인 대기)

   ## AI 판단
   - <AI가 스스로 내린 중요한 판단과 이유>

   ## 변경
   ## 검증
   <실행한 것과 결과. 실행하지 않았으면 "실행하지 않음">

   TASK-N
   Closes #<이슈>
   ```

   거부·대체된 기록, 확인 대기 중인 추론을 확정 결정처럼 쓰지 않는다. 이슈가 없으면 `Closes` 줄을 뺀다.
   AI 협업 방식에 대한 지시는 PR에 도움이 될 때만 넣는다.
4. 초안을 보여 준다. PR 생성·푸시는 사용자가 요청할 때만, 저장소 규칙대로 한다.
