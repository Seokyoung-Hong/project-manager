## 제1조 개인정보 처리 목적과 근거

쿼넥트는 다음 목적으로 개인정보를 처리합니다.

1. 계정 관리: 회원 식별, 로그인, GitHub 계정 식별, 문의 응답, 로그인 남용 차단을 수행합니다. 쿼넥트는 계정 실명을 직접 수집하여 조직 안에서 본인을 식별하고 조직 관리자가 구성원을 확인하도록 합니다. 실명 표시 설정을 켠 조직에서는 실명을 해당 조직의 표시 이름으로 사용합니다.
2. 업무 협업: 조직·팀의 권한 관리, 업무 배정, 태스크·댓글·문서·회의록·첨부 파일 관리, 변경 이력과 결정 기록 보존, 개인 포트폴리오 작성을 지원합니다.
3. 외부 연동: GitHub 로그인과 저장소·이슈·PR 연동, Discord 알림·명령·채널 권한 관리, 이용자가 승인한 AI 도구의 업무 접근을 지원합니다.
4. 선택한 AI 기능: 회의 음성을 전사하고 회의록 초안을 작성하며 웹에서 요청한 내용의 요약을 제공합니다. 조직이 AI 자동완성을 켠 경우에만 이용자의 요청에 따라 AI 자동완성과 태스크 후보 뽑기를 제공합니다. 해당 기능에 필요한 내용만 선택한 AI 서버에 전송합니다.
5. 운영과 보안: 운영자 행위를 감사하고 접속 장애와 부정 이용에 대응하며 데이터를 백업합니다.

계정 실명과 조직 표시 이름은 쿼넥트가 서비스의 이름 표시 기능을 위해 처리합니다. 실명을 제외한 조직별 구성원 정보는 각 조직이 처리 목적과 수집 항목을 정합니다. 해당 정보의 수집·이용은 각 조직의 방침에 따르며 조직은 적법한 처리 근거를 확보하고 필요한 고지와 동의를 이행해야 합니다. 쿼넥트는 조직의 설정에 따라 정보를 저장하고 해당 조직 관리자에게 제공하는 인프라를 운영합니다. 조직의 방침은 관계 법령과 유달리 이용약관을 준수해야 합니다. 이 역할 구분은 쿼넥트의 법적 의무나 정보주체의 권리를 제한하지 않습니다.

아래의 계약 체결·이행 근거는 조직이 정하는 구성원 정보의 모든 수집·이용에 일괄 적용되는 근거를 뜻하지 않습니다. 조직은 해당 정보의 처리 근거를 별도로 판단하고 구성원에게 안내합니다.

계정 관리와 업무 서비스 제공에 필요한 처리는 「개인정보 보호법」 제15조제1항제4호의 계약 체결·이행을 근거로 합니다. 서비스 이행에 필요한 인증 남용 차단과 보안·운영 기록 처리는 같은 항 제4호를 근거로 합니다. GitHub·Discord 개인 연결과 AI 연결의 국외 이전(제3자 제공)은 제17조제1항제1호와 제28조의8제1항제1호에 따라 처음 연결할 때 별도 동의를 받습니다. 동의 화면과 철회 방법은 제4조에 기재합니다.

목적을 변경할 때에는 법에서 요구하는 동의나 고지 절차를 이행합니다.

AI 자동완성 전송은 조직 관리자가 관리하는 AI 자동완성 사용 설정과 이용자의 요청에 따라 이루어집니다. 이 설정은 기본으로 켜져 있으나 AI 등록과 요청이 있어야 전송합니다. 끄면 해당 조직의 내용으로 조직 AI와 개인 AI를 모두 사용할 수 없습니다. 유달리는 처리방침·이용약관에서 처리 내용을 고지하고, 가입 및 다음 로그인 시 적용 문서의 버전을 확인하여 동의를 받는 기존 절차를 이 기능의 기본 동의 절차로 운영합니다. 이 기능만을 위한 개인별 동의 화면은 두지 않습니다. 조직 설정과 이용자의 문서 동의는 다른 정보주체의 동의나 법에서 별도로 요구하는 절차를 대신하지 않습니다. 국외 이전의 구체적인 처리와 근거는 제6조에 기재합니다.

실명이 없는 기존 이용자는 개정 적용 후 다음 로그인 때 실명을 입력해야 서비스를 이용할 수 있습니다. 기존 조직별 실명은 계정 실명으로 이전하며, 서로 다른 실명이 있으면 본인이 후보 중 올바른 실명을 선택하거나 직접 입력합니다. 후보는 실명 저장 후 삭제합니다.

조직 표시 이름은 해당 조직에서 사용하는 이름이며, 입력하지 않으면 계정의 표시 이름을 사용합니다. 본인 또는 해당 조직 관리자가 변경할 수 있고 구체적인 변경 방법은 서비스 화면·도움말에서 안내합니다. 실명 표시 설정을 켠 조직에서는 계정 실명을 사용하며 조직 표시 이름을 변경할 수 없습니다.

조직별 구성원 정보의 항목은 조직마다 다르며 서비스가 미리 정한 고정 목록이 아닙니다. 필수 항목을 입력하지 않으면 해당 조직의 웹·API·AI 스킬·MCP를 통한 서비스를 이용할 수 없습니다. 선택 항목의 입력 여부는 구성원이 정합니다. 조직은 수집 전에 항목·목적·필수 여부·보유 기간·관리자 열람 범위·권리 행사 창구와 필수 항목 미입력 시 영향을 안내해야 합니다.

유달리 이용약관에 따라 조직과 관리자는 민감정보(「개인정보 보호법」 제23조), 고유식별정보(주민등록번호·여권번호·운전면허번호·외국인등록번호 등, 제24조·제24조의2), 계좌번호·카드번호 등 금융정보와 그 밖의 중요 개인정보를 구성원 정보로 요구해서는 안 됩니다. 위반 시 쿼넥트는 해당 항목과 입력값 삭제, 기능 제한 또는 이용 정지 조치를 할 수 있습니다.

서비스 이용 중 다음 정보가 자동으로 수집됩니다.

| 항목 | 목적 |
|---|---|
| 접속 IP, 로그인 시도 아이디, 로그인 실패·가입 횟수 | 무차별 로그인과 가입 남용을 차단합니다. 존재하지 않는 아이디의 로그인 시도도 기록될 수 있습니다. |
| 앞단 프록시(Nginx Proxy Manager)의 접속 IP·요청 주소·상태·Referer·User-Agent | 장애 대응과 보안 점검을 수행합니다. 앱 자체의 접속 로그는 남기지 않습니다. |
| 세션 정보와 세션 쿠키, CSRF 쿠키, 알림 표시 쿠키 | 로그인 상태를 유지하고 위조 요청을 방지합니다. 세션에는 인증 방식과 현재 조직 정보가 포함됩니다. |
| 운영자 감사 기록의 행위자·대상·사유·변경 전후·IP | 운영자 조치의 적정성을 확인합니다. |
| 업무 변경 이력의 대상·필드·이전값·새값·행위자·외부 로그인명·출처·토큰 참조 | 업무 변경을 추적합니다. |

조직이 연결한 비공개 Discord 채널에서는 유달리 비회원의 Discord 사용자 ID와 표시 이름도 채널 권한 점검을 위해 수신할 수 있습니다. 채널 관리 해제 또는 관리자의 허용 철회 시 삭제합니다. 점검 완료·채널 퇴장만으로는 삭제하지 않습니다. 해당 비회원도 제9조의 창구로 권리를 행사할 수 있습니다.

민감정보와 주민등록번호·여권번호·운전면허번호·외국인등록번호를 가입 항목으로 요구하지 않습니다. 업무 본문, 파일, 음성에 본인이나 다른 사람의 민감정보를 넣지 마십시오. 업무 자료는 조직·프로젝트 권한과 가시성 설정에 따라 다른 구성원에게 보일 수 있습니다. 입력한 자료의 공개 범위를 확인하고 불필요한 개인정보는 삭제하거나 삭제를 요청하십시오.

| AI 자동완성 관련 구분 | 처리 항목 | 목적·수집 방법 |
|---|---|---|
| 선택: 개인 AI 설정 | 이용자가 정한 이름·AI 종류, 주소 방식의 AI 서버 주소·모델·암호화한 키, 사용 여부·사용 순서, 연결할 내 PC 식별 정보, 최근 연결 성공 시각·오류 코드 | 이용자가 서비스 화면의 AI 설정 메뉴에서 등록하며, AI 요청과 연결 관리를 위해 처리합니다. “Codex(내 구독, 내 PC)”는 AI 서버 주소·키를 등록하지 않으며, 유달리 서버는 이용자의 OpenAI 구독 인증 토큰을 받거나 보관하지 않습니다. |
| 선택: 조직 AI 설정 | 조직 AI 서버 주소·모델·암호화한 키, 사용 권한·하루 한도·AI 자동완성 사용 여부 | 조직 관리자가 조직 설정에서 등록하며, 조직의 요청 경로와 사용 권한을 관리합니다. |
| 선택: 내 PC의 Codex 상태·웹 로그인 | 연결된 PC의 Codex CLI 설치 여부·버전·로그인 여부, 로그인·로그아웃 요청 상태, 기기 코드·인증 주소·만료 시각·오류 코드 | 내 PC 연결 프로그램의 주기적인 상태 보고(heartbeat)로 설치·버전·로그인 여부를 서버에 보내 연결 상태를 안내합니다. 웹에서 Codex 로그인을 시작하면 PC가 보낸 기기 코드와 인증 주소를 만료 시각(최대 15분)까지 서버에 임시 저장합니다. 로그인 완료·실패 또는 만료 시 코드와 주소를 지웁니다. OpenAI 구독 인증 토큰과 Codex 인증 파일은 PC 밖으로 보내지 않습니다. |
| 선택: AI 서비스 계정으로 연결 | OpenRouter가 발급한 키, Hugging Face 접근·갱신 토큰과 만료 시각, 연결 서비스·모델·사용 순서 | 이용자가 서비스 화면의 AI 설정 메뉴에서 해당 서비스 계정으로 연결하면 키 또는 토큰을 받아 암호화하여 보관하고 요청 인증과 토큰 갱신에 사용합니다. GitHub Copilot은 이미 연결한 GitHub 사용자 토큰을 이 용도로도 사용하며 개인 AI 설정에 별도 GitHub 토큰을 복사하여 저장하지 않습니다. |
| AI 요청·작업 기록 | 요청자·조직, 작업 종류·대상·상태, 이용자가 입력한 요청 내용, 적용 옵션, 결과·태스크 후보, 시각·사용량·오류 코드 | AI 요청 시 생성하여 처리 상태, 미리보기·적용과 하루 한도를 관리합니다. 요청에 필요한 업무 맥락은 실행 시 접근 권한 안에서 조립합니다. |

AI에 보내는 항목은 요청한 입력 칸, 문서·회의록·전사문 또는 GitHub 이슈 본문과 요청 처리에 필요한 업무 맥락입니다. 맥락에는 관련 프로젝트·태스크 정보와 다른 구성원의 조직 표시 이름이 포함될 수 있습니다. 실명 표시 설정을 켠 조직에서는 계정 실명이 이름으로 포함됩니다. 모든 조직 자료를 일괄 전송하지 않으며 요청자의 접근 권한 안에서 필요한 범위로 제한합니다. 서버 주소의 연결 확인과 모델 목록 조회에는 업무 본문을 보내지 않습니다.

## 제3조 보유 기간

다음 기간은 유달리의 보관 기준입니다. 법정 의무 보관 기간으로 정한 값이 아니라 서비스 제공과 보안을 위한 운영 기준입니다. 외부 제공자의 보관 기준은 제6조에서 별도로 안내합니다.

| 정보 | 보유 기간·종료 시점 | 보관 이유 |
|---|---|---|
| 계정 실명·이전 충돌 후보 | 계정 실명과 남아 있는 후보는 회원 탈퇴 시 삭제합니다. 후보는 실명 저장 시에도 삭제하며 백업 사본은 제7조에 따릅니다. | 계정의 본인 식별과 실명 이전 확인 |
| 조직 표시 이름 | 조직 탈퇴 또는 조직 삭제 시 삭제하며 회원 탈퇴 시에도 삭제합니다. 백업 사본은 제7조에 따릅니다. | 조직 안의 이름 표시 |
| 계정 식별 정보·이메일·인증 정보·개인 설정·오늘 목록·포트폴리오 초안 | 회원 탈퇴 처리 시 삭제하거나 제8조에 따라 대체합니다. | 계정과 개인 기능 제공 |
| 조직별 구성원 정보 | 조직 탈퇴 시 해당 조직의 구성원 정보는 삭제합니다. 조직 삭제 시에도 함께 삭제합니다. 삭제 후 백업 사본의 처리는 제7조에 따릅니다. | 각 조직이 정한 목적에 따른 구성원 정보 저장·제공 |
| GitHub 사용자 연결 정보·토큰 | 연결 해제 또는 회원 탈퇴 시 유달리 저장분을 삭제합니다. | 외부 계정 연결 |
| Discord 계정 연결 정보 | 연결 해제 또는 회원 탈퇴 시 삭제합니다. | 본인 확인과 알림 |
| 조직의 외부 연동 설정 | 조직 연결 해제 또는 조직 삭제 시 삭제합니다. | 조직 연동 제공 |
| GitHub 수신 활동 정보 | 저장소 연결 또는 프로젝트 삭제 시 삭제합니다. | 저장소 업무 연동 |
| 업무 변경 이력 | 조직이 존속하는 동안 보관합니다. | 업무 변경 추적 |
| 태스크·댓글·회의록·문서·결정 기록 | 조직 업무 기록으로 보관합니다. 탈퇴 시 작성자 식별 정보를 제8조와 같이 대체합니다. 세부 삭제 제한은 제7조에 기재합니다. | 조직의 업무 연속성 |
| 앞단 프록시 접속 로그 | 기록일로부터 최대 90일. 로그 회전에 따라 더 일찍 삭제될 수 있습니다. | 운영과 장애·보안 대응 |
| 운영자 감사 기록 | 기록일로부터 1년(365일)이 지난 뒤 매일 정리 작업에서 삭제합니다. 백업 사본은 그 뒤에도 최대 30일 남을 수 있습니다. | 운영자 행위 추적 |
| 백업 | 백업 생성일로부터 30일 후 자동 삭제 | 장애 복구 |
| 세션 | 쿠키 유효 기간은 생성·갱신에 따른 만료 시점까지 14일입니다. 만료된 서버 기록은 매일 정리 작업에서 삭제하며 탈퇴 시 모든 세션을 삭제합니다. | 로그인 유지 |
| 로그인 실패·잠금 기록 | 마지막 갱신 후 1일이 지난 기록은 매일 정리 작업에서 삭제합니다. 잠금 중인 기록은 잠금 종료 후 정리합니다. 로그인 성공 시 아이디 실패 카운터는 삭제합니다. | 인증 남용 차단 |
| 회의 오디오 | 녹음 종료 후 기본 7일. 조직 설정으로 0~30일을 선택할 수 있습니다. 오디오는 백업하지 않습니다. | 회의 전사 |
| 회의 전사문·문서 수정 이력 | 회의록·문서의 업무 기록으로 보관합니다. 문서 수정 이력은 해당 문서 삭제 시 삭제합니다. | 회의 기록과 문서 복구 |
| 비회원 Discord 채널 권한 점검 정보 | 채널 관리 해제 또는 관리자의 허용 철회 시 삭제합니다. 점검 완료·채널 퇴장만으로는 삭제하지 않습니다. | 비공개 채널 접근 확인 |

구성원 정보의 수집·이용과 보유에 관한 각 조직의 방침은 위 서비스 삭제 기준 안에서 적용합니다. 각 조직은 목적에 필요한 기간만 보유하고 목적이 끝난 정보는 삭제해야 합니다. 조직의 방침이 조직 탈퇴·삭제 후 유달리의 보유를 연장하는 것은 아닙니다.

만료된 API·AI 토큰은 매일 정리 작업에서 삭제합니다. OAuth 인가 코드는 생성 후 1일이 지나면 사용 여부와 관계없이 정리합니다. 폐기만 하고 만료되지 않은 토큰은 목록 표시를 위해 남으며 탈퇴 시 모든 토큰과 인가 코드를 삭제합니다.

동의 기록은 회원 이용 기간 동안 보관합니다. 탈퇴자의 기록은 철회 시각부터 1년(365일)이 지난 뒤 매일 정리 작업에서 삭제합니다. 탈퇴 시 아직 유효한 동의에는 탈퇴 시각을 철회 시각으로 기록하므로 이 기록은 탈퇴 후 1년간 보관합니다. 탈퇴 전에 철회한 기록은 더 일찍 삭제됩니다.

Discord 봇 로컬 DB의 DM 채널·발송 기록·주간 보고·채널 권한 부여 기록에는 정기 삭제 기한을 두지 않으며 탈퇴만으로 모두 삭제되지 않습니다. 유달리의 개인 알림 큐와 사용자별 Discord 권한 보고는 탈퇴 시 삭제합니다. OAuth 클라이언트 등록 정보에는 별도의 정기 삭제 기한을 두지 않습니다. 나머지 기록과 파일의 삭제 요청은 제9조의 창구로 접수합니다.

| AI 관련 정보 | 보유 기간·종료 시점 | 보관 이유 |
|---|---|---|
| 개인 AI 설정·암호화한 키 | 이용자가 해당 개인 AI를 삭제하거나 회원 탈퇴 시 삭제합니다. | 개인 AI 연결과 사용 순서 관리 |
| OpenRouter 발급 키·Hugging Face 접근·갱신 토큰 | 해당 개인 AI 삭제 또는 회원 탈퇴 시 유달리 저장분을 삭제합니다. AI를 끄는 것만으로 삭제하지 않습니다. 외부 서비스의 키·앱 권한은 이용자가 해당 서비스에서 직접 폐기해야 합니다. | 계정으로 연결한 개인 AI의 인증·토큰 갱신 |
| 내 PC의 Codex 설치·버전·로그인 상태 | 상태 보고 시 갱신하며 내 PC 연결 해제 또는 회원 탈퇴 시 삭제합니다. | 설치·로그인 상태와 연결 지원 여부 안내 |
| Codex 웹 로그인 기기 코드·인증 주소 | 로그인 완료·실패 또는 만료 시 삭제합니다. 유효 기간은 최대 15분이며 만료된 값은 정리 시 지웁니다. | 이용자가 시작한 PC의 Codex 로그인 안내 |
| 조직 AI 설정·암호화한 키 | 관리자가 해당 설정을 삭제하거나 조직 삭제 시 삭제합니다. AI 자동완성을 끄는 것만으로 저장한 설정이 삭제되지는 않습니다. | 조직 AI 연결과 권한 관리 |
| AI 작업 기록·요청 내용·결과·태스크 후보 | 생성일로부터 7일 보관한 뒤 정리 작업에서 삭제하며, 요청자가 회원 탈퇴하면 삭제합니다. | AI 요청 처리, 결과 미리보기와 적용 |

AI 결과를 적용한 업무 본문과 만든 태스크는 AI 작업 기록과 구분되는 조직 업무 기록입니다. 문서·회의록의 적용 전 본문은 이전 버전에 남으며, 작업 기록의 7일 보유 기간이 적용된 본문·태스크·이전 버전의 삭제 기간을 뜻하지 않습니다. 백업 사본은 제7조에 따릅니다. 외부 AI 서버가 받은 내용의 보유 기간은 제6조에 따릅니다.

## 제4조 개인정보의 제3자 제공과 이용자 연결

계정 실명은 본인, 서비스 운영자와 이용자가 소속된 모든 조직의 관리자가 열람합니다. 조직 가입 또는 초대 수락으로 해당 조직의 구성원이 되면 그 조직 관리자에게 실명이 보입니다. 관리자는 실명 표시 설정과 무관하게 구성원 목록에서 실명을 열람합니다. 이 열람은 조직 안의 본인 식별과 구성원 확인을 위한 것이며 목적을 벗어난 이용·공개는 허용되지 않습니다.

실명 표시 설정을 켜면 해당 조직 구성원 전원에게 실명이 표시되며, 해당 조직의 이름을 사용하는 AI 요청·MCP·API 응답·Discord 알림과 명령 응답·회의 전사 용어집에도 실명이 포함됩니다. AI 및 전사 서버나 Discord로 전송되는 실명의 수신자·목적·방법·보유 기간과 거부 방법은 제5조·제6조의 해당 경로에 따릅니다. 조직 설정이나 이용자의 문서 동의는 다른 구성원의 동의 또는 법에서 요구하는 별도 절차를 대신하지 않습니다.

GitHub 이슈·댓글 등 저장소 연동으로 나가는 글의 작성자 이름은 계정의 표시 이름을 사용하며 계정 실명을 이름으로 전송하지 않습니다. 업무 본문에 이용자가 입력한 실명과 GitHub Copilot에 전달하는 AI 업무 맥락은 이 작성자 이름 규칙과 구분됩니다.

실명을 제외한 조직별 구성원 정보의 입력값은 해당 조직 관리자가 열람합니다. 조직은 그 정보의 수집 항목과 목적을 정하는 주체이며 쿼넥트는 저장·제공 인프라를 운영합니다. 관리자의 수집·이용과 열람은 각 조직의 방침 및 관계 법령에 따릅니다. 조직은 수집 전에 관리자 열람 범위와 목적을 구성원에게 알려야 합니다. 이 방침의 게시나 필수 항목 입력만으로 별도 동의가 필요한 제공·처리의 동의를 갈음하지 않습니다.

GitHub 로그인·계정 연결, Discord 개인 연결, AI용 토큰 발급·MCP 커넥터 승인을 처음 진행할 때 국외 이전(제3자 제공) 동의를 받습니다. 화면에는 받는 자의 법인명·연락처, 국가, 항목, 목적, 시기·방법, 보유 기간과 거부권·거부 시 불이익을 안내합니다. 대상별 상세 내용은 별표 2의 표에 기재합니다. 본 방침의 게시나 기능 선택만으로 동의를 갈음하지 않습니다.

이용자는 동의를 거부할 수 있습니다. 동의하지 않으면 해당 연결 기능을 사용할 수 없으며 아이디로 가입하여 다른 기능을 이용할 수 있습니다. 동의 화면 도입 전에 연결한 이용자의 안내 기간과 미동의 연결의 사용 중지는 별표 2에 기재합니다.

서비스 화면의 동의 관리 메뉴에서 대상별 동의를 철회할 수 있습니다. 철회하면 GitHub·Discord 연결을 끊거나 AI용 토큰·커넥터 접근을 차단합니다. GitHub로만 로그인하는 계정은 비밀번호를 먼저 설정하거나 회원 탈퇴 절차를 이용합니다. 비밀번호 재설정 링크는 운영자에게 요청할 수 있습니다. 이메일로도 동의 철회를 요청할 수 있습니다.

AI 연결(MCP)은 OpenAI·Anthropic에 한정되지 않습니다. 이용자가 선택한 AI 클라이언트는 승인한 토큰 범위와 그 이용자의 조직·프로젝트 권한 안에서 업무를 조회하거나 변경합니다. 응답에는 다른 구성원의 ID·조직 표시 이름·Discord ID를 비롯한 조직 데이터가 포함될 수 있습니다. 실명 표시 설정을 켠 조직에서는 표시 이름에 계정 실명이 포함됩니다. 결정 기록의 원문은 MCP로 받거나 내보내지 않습니다. 이용자의 연결 동의는 다른 구성원의 동의를 대신하지 않습니다. 해당 정보의 열람·삭제·처리정지 요청은 제9조의 창구로 접수합니다.

외부 서비스에 이미 생성된 이슈·메시지·대화는 연결 해제나 동의 철회만으로 삭제되지 않습니다. 유달리는 GitHub 쪽 앱 권한을 철회하지 않으므로 GitHub의 앱 권한 관리 화면에서 이용자가 직접 권한을 철회해야 합니다. 외부 서비스에 저장된 자료의 삭제는 해당 사업자의 절차를 따릅니다.

AI 자동완성·태스크 후보 뽑기는 위의 AI용 토큰·MCP 연결과 다른 기능입니다. 조직 AI는 조직 관리자가 지정한 서버에, 개인 AI는 이용자가 등록한 서버 또는 “Codex(내 구독, 내 PC)”를 통해 OpenAI에 요청합니다. AI 운영자가 내용을 처리하는 목적과 계약에 따라 처리위탁 또는 제3자 제공 여부가 달라질 수 있으므로, 조직과 개인 AI 이용자는 필요한 고지·적법한 처리 근거를 확보해야 합니다. 쿼넥트는 자신의 처리 범위에 관한 법적 의무를 이행하며, 정보주체는 제9조의 창구로 권리를 행사할 수 있습니다.

개인 AI에는 계정으로 연결한 OpenRouter·Hugging Face와 GitHub Copilot도 포함됩니다. OpenRouter·Hugging Face 경로는 유달리 서버가 해당 서비스와 그 서비스를 통해 선택되는 모델 처리 사업자에 업무 내용을 전송합니다. GitHub Copilot 경로는 기존 GitHub 연결 토큰을 인증에 사용하여 유달리 서버가 GitHub로 업무 내용을 전송합니다. GitHub 로그인·저장소 연결과 Copilot의 업무 내용 전송은 목적과 항목이 다르며 기존 연결 동의가 추가 처리에 필요한 절차를 모두 대신한다는 뜻은 아닙니다.

## 제5조 개인정보 처리위탁

쿼넥트는 선택한 AI 기능과 조직 관리자가 연결한 Discord 채널·GitHub 조직 연동을 제공하기 위해 다음 업무를 맡깁니다. 기능을 사용할 때 필요한 내용만 전송하며 이용자가 직접 연결한 AI 클라이언트의 업무 접근은 제4조의 제3자 제공과 구분합니다.

수탁자·연락처, 위탁 업무와 위탁 기간은 문서 끝 별표 1에 기재합니다.

서버와 백업은 대한민국의 자체 서버에서 운영합니다. 백업은 같은 서버 안에 보관하며 운영자만 접근합니다. 외부 장소에 백업하지 않습니다. 글꼴은 자체 호스팅하여 제공하며 글꼴을 불러오기 위한 외부 사업자 요청은 발생하지 않습니다. 수탁자가 변경되면 처리방침에 공개합니다.

AI 자동완성·태스크 후보 뽑기에 사용하는 조직 AI의 운영자는 조직 관리자가, 주소 방식의 개인 AI 운영자는 등록 이용자가 정합니다. 동일한 OpenAI 호환 규격을 사용하더라도 운영자는 OpenAI에 한정되지 않습니다. “Codex(내 구독, 내 PC)”의 외부 AI 운영자는 OpenAI입니다. 요청 처리만을 맡기는 경우 AI 운영자의 위탁 범위·목적 외 이용 제한·재위탁·보호 조치와 보유·삭제 조건을 확인합니다. 이용자의 내 PC를 거쳐 요청하는 경우 연결한 기기는 이용자 자신의 기기이며, 그 PC가 등록한 AI 서버에 요청하거나 로그인된 Codex CLI를 통해 OpenAI에 요청합니다. 내 PC를 거친다는 이유만으로 국내 처리 또는 외부 전송 없음이 보장되지는 않습니다. 실제 서버 운영자와 처리 국가에 따라 제6조의 국외 이전 안내가 적용됩니다.

계정으로 연결한 개인 AI의 사업자와 처리 조건은 별표 1·별표 2에 기재합니다.

## 제6조 국외 이전

국외 이전에는 국외 제3자 제공·처리위탁·보관이 포함됩니다. 이전받는 자·연락처, 국가, 항목, 목적, 시기·방법, 보유 기간, 거부 방법과 효과 및 적용 근거는 문서 끝 별표 2에 경로별로 기재합니다. 별표는 이 방침의 일부이며 전송 전에 해당 경로의 안내를 확인할 수 있습니다.

개인 연결의 별도 동의와 철회는 제4조의 절차에 따릅니다. 일반 문서 동의나 조직 설정은 별도 동의가 필요한 제공·이전 및 다른 정보주체의 동의를 대신하지 않습니다. 국외 이전의 중지·삭제는 제9조의 창구로도 요청할 수 있습니다. 수신자나 처리 조건이 바뀌면 별표를 갱신하고 법령상 필요한 고지·동의 절차를 이행합니다.

## 제7조 파기 절차와 방법

쿼넥트는 보유 기간이 끝나거나 처리 목적을 달성한 정보를 삭제 대상으로 확인하여 지체 없이 삭제합니다. 전자적 정보는 시스템에서 삭제합니다. 감사 기록·만료 세션·만료 토큰·OAuth 인가 코드·로그인 잠금 기록·탈퇴자 동의 기록은 매일 정리 작업에서 기한 경과 여부를 확인하여 삭제합니다. 복구용 백업에 남은 사본은 생성 후 30일의 보관 기간이 끝나면 삭제합니다. 백업 사본은 통상적인 서비스 조회에 사용하지 않습니다.

탈퇴 후에도 남는 조직 업무 기록은 제8조에 따라 작성자 식별 정보를 대체합니다. 이 조치가 본문에 포함된 이름이나 맥락까지 모두 제거하는 것은 아닙니다. 본문 속 개인정보는 별도로 삭제를 요청할 수 있습니다.

결정 기록이 연결된 태스크는 업무 기록 보호를 위해 삭제가 제한될 수 있습니다. 첨부 파일의 참조와 파일 본체는 구분하여 처리하며 파일 본체의 실제 삭제 여부는 삭제 요청 처리 과정에서 확인합니다.

다른 법률이 보존을 요구하는 경우에는 법률의 근거·항목·기간을 확인하여 서비스용 정보와 분리하고 그 보존 목적에만 사용합니다.

AI 작업 기록은 제3조의 보유 기간이 지난 뒤 정리 작업에서 삭제합니다. 삭제된 작업 기록의 백업 사본은 백업 보유 기간에 따라 처리합니다.

## 제8조 회원 탈퇴와 탈퇴 후 처리

서비스 화면의 설정 메뉴에서 본인 확인 절차를 거쳐 직접 탈퇴할 수 있습니다. 구체적인 조작 방법은 서비스 화면·도움말에서 안내하며, 직접 처리가 어려운 경우 제9조의 창구로 요청할 수 있습니다. 조직의 마지막 관리자는 다른 관리자에게 권한을 넘긴 뒤 탈퇴할 수 있습니다.

탈퇴 시 다음과 같이 처리합니다.

1. 비밀번호를 사용할 수 없도록 변경하고 계정 실명·실명 이전 후보·이메일과 개인 설정을 삭제합니다. 계정을 비활성화합니다.
2. 모든 API·AI·MCP OAuth 토큰, OAuth 인가 코드, GitHub 계정 연결과 토큰, Discord 개인 연결·연결 코드를 삭제합니다. 유달리는 GitHub 쪽 앱 권한을 철회하지 않으므로 GitHub의 앱 권한 관리 화면에서 이용자가 직접 철회해야 합니다.
3. 오늘 목록, 포트폴리오 초안·출처 스냅샷, 개인 Discord 알림 큐, 사용자별 Discord 권한 보고와 모든 세션을 삭제합니다.
4. 조직 표시 이름과 실명을 제외한 구성원 정보, 조직·팀 소속을 삭제하고 프로젝트 관리자 지정을 해제합니다. 진행 중인 녹음의 진행자가 탈퇴하면 녹음을 종료합니다. 탈퇴 시 현재 소속된 조직의 모든 녹음 기록에서 진행 중 여부와 관계없이 본인의 Discord ID·닉네임을 지우고 표시 이름을 탈퇴한 사용자로 바꿉니다. 탈퇴 전에 이미 떠난 조직의 녹음 기록은 이 삭제 대상에 포함되지 않습니다.
5. 아이디를 `deleted-<id>`로 바꾸고 표시 이름을 탈퇴한 사용자로 대체합니다. 같은 대체 아이디가 이미 있으면 난수를 덧붙입니다. 태스크·댓글·회의록·문서·첨부 파일·변경 이력·결정 기록은 조직 업무 기록으로 남습니다.
6. 운영자 감사 기록은 기록일로부터 1년(365일)이 지난 뒤 매일 정리 작업에서 삭제합니다. 동의 기록은 제3조의 철회 시각 기준으로 1년간 보관합니다. 백업은 생성일로부터 30일 후 삭제하므로 서비스에서 지운 정보도 백업에는 최대 30일 남을 수 있습니다. 앞단 프록시 접속 로그는 기록일로부터 최대 90일 보관합니다.

GitHub 연결 정보가 삭제되어도 GitEvent·이슈·변경 이력 같은 업무 기록에 포함된 GitHub 공개 로그인명은 남습니다. Discord 봇 로컬 DB에 저장한 Discord 사용자 ID와 DM 채널 ID의 대응 기록도 탈퇴만으로 삭제되지 않습니다. 업무 본문·첨부 파일 속 이름이나 다른 식별 정보까지 일괄 삭제하지 않으며 필요한 경우 제9조의 창구로 삭제를 요청할 수 있습니다.

탈퇴 처리는 되돌릴 수 없습니다. 기존 아이디로 다시 가입할 수 있으나 이전 계정과 업무 기록이 복원되지는 않습니다. 계정 식별 정보를 대체하는 조치만으로 남은 업무 기록이 완전히 익명화되지는 않습니다.

7. 등록한 개인 AI 정보와 암호화한 키(OpenRouter 발급 키 포함)·Hugging Face 접근·갱신 토큰, 내 PC 연결의 Codex 상태·웹 로그인 정보, 본인이 요청한 AI 작업 기록·요청 내용·결과·태스크 후보를 삭제합니다. OpenRouter 키·Hugging Face 앱 권한·GitHub 앱 권한의 외부 서비스 쪽 폐기와 PC의 Codex 로그아웃은 이용자가 직접 해야 합니다. 이미 업무 본문에 적용한 결과와 만든 태스크는 조직 업무 기록으로 남으며 본문 속 개인정보는 제9조에 따라 삭제를 요청할 수 있습니다.

## 제9조 정보주체·법정대리인의 권리와 행사 방법

이용자는 본인 개인정보의 열람·정정·삭제·처리정지 및 동의 철회를 요청할 수 있습니다.

- 설정 화면: 계정 실명·표시 이름 수정, 조직 표시 이름 수정(실명 표시 설정을 켠 조직 제외), 개인정보 동의 철회, GitHub·Discord 연결 해제, API 토큰 폐기, DM 알림 설정, 회원 탈퇴를 할 수 있습니다.
- 이메일: [contact@quanect.kr](mailto:contact@quanect.kr)로 요청 항목과 내용을 보낼 수 있습니다. 아이디·이메일 정정, 일괄 열람이나 업무 본문 속 개인정보 삭제도 이 창구로 요청합니다.
- 우편: 경기도 시흥시 산기대학로 237, P동 306-10호, 쿼넥트 개인정보 보호책임자 앞으로 요청할 수 있습니다.

쿼넥트는 본인 또는 정당한 대리인인지 확인하고 법정 기한에 따라 처리 결과를 알립니다. 대리인은 위임 관계를 확인할 수 있는 자료를 제출할 수 있습니다. 요청을 제한하거나 거절하는 경우에는 법적 근거와 사유를 설명합니다. 다른 사람의 권리 또는 법률상 보존 의무가 있는 기록은 삭제·열람이 제한될 수 있습니다.

조직별 구성원 정보의 수집 항목·목적·필수 여부와 조직의 이용에 관한 문의 및 권리 행사 요청은 해당 조직 관리자에게 할 수 있습니다. 쿼넥트의 저장·제공에 관한 요청은 위 이메일과 우편 창구로도 접수합니다. 조직 관리자에게만 요청해야 하는 것은 아니며 쿼넥트는 자신의 처리 범위에 관한 법적 의무에 따라 대응합니다.

개인정보 전송요구는 법령상 적용 범위에 따라 처리합니다. 전송을 요청할 항목과 수신처를 이메일로 보내면 적용 여부와 처리 방법을 안내하며 진행 상태와 처리 내역도 같은 창구로 확인할 수 있습니다. 문서·포트폴리오 내보내기 기능은 법정 전송요구 절차와 구분됩니다.

이용자는 다른 사람의 개인정보를 무단으로 등록·공개하지 않아야 하며 계정과 토큰을 안전하게 관리해야 합니다.

## 제10조 아동과 AI 기능

만 14세 미만은 가입할 수 없습니다. 현재 가입 절차에서는 비밀번호 가입과 GitHub를 통한 최초 가입 모두 만 14세 이상임을 확인합니다. 이 확인 절차 도입 전에 가입한 이용자에게 소급하여 확인한 것은 아닙니다. 가입 제한과 관계없이 아동의 개인정보가 처리된 사실을 발견한 법정대리인은 제9조의 창구로 열람·정정·삭제·처리정지를 요청할 수 있습니다.

AI 기능은 회의 전사·초안·요약, AI 자동완성과 태스크 후보 뽑기, 이용자가 승인한 업무 도구 접근을 지원합니다. AI 자동완성 결과는 적용 전에 미리보기로 확인하며, 태스크 후보는 담당자·기한과 내용을 확인·수정한 뒤 이용자가 생성 여부를 판단합니다. 채용·신용평가처럼 이용자의 권리·의무에 중대한 영향을 미치는 완전 자동 결정을 하는 기능은 제공하지 않습니다. AI가 작성한 업무 내용의 정정·삭제와 AI 처리에 관한 설명은 이메일로 요청할 수 있습니다.

AI 자동완성 결과의 적용 여부는 이용자가 판단합니다. 문서·회의록 본문을 적용하면 적용 전 본문은 이전 버전에 남습니다.

## 제11조 자동 수집 장치의 운영과 거부

유달리는 로그인 유지용 `sessionid`, 위조 요청 방지용 `csrftoken`, 알림 문구를 한 번 표시하기 위한 `messages` 쿠키를 사용합니다. 세션 쿠키의 유효 기간은 14일이며 CSRF 쿠키는 기본 1년입니다. 광고 식별자나 맞춤형 광고를 위한 쿠키는 사용하지 않습니다.

브라우저 설정에서 이 사이트의 저장된 쿠키를 삭제하거나 사이트별 쿠키 저장을 차단할 수 있습니다. 쿠키를 차단하면 로그인 유지와 인증이 필요한 요청을 이용하기 어렵습니다.

화면의 패널 너비와 접힘 상태는 브라우저의 localStorage에 저장합니다. 브라우저의 사이트 데이터 삭제 기능으로 지울 수 있습니다. 글꼴은 유달리 서버에서 제공하며 외부 글꼴 서비스로 접속정보를 보내지 않습니다.

## 제12조 안전성 확보 조치

쿼넥트는 실제 서비스에 다음 조치를 적용합니다.

1. 접근 관리: 조직 역할, 프로젝트 등급·가시성, 토큰 범위와 AI 접근 정책으로 권한을 제한합니다. 첨부 파일 다운로드 시 권한을 확인하며 관리 화면은 최고 운영자만 접근할 수 있습니다.
2. 인증 정보 보호: 비밀번호는 PBKDF2-SHA256 해시, API 토큰·인가 코드는 SHA-256 해시로 저장합니다. GitHub 사용자 토큰, 조직 전사 서버 키와 조직 AI·개인 AI 서버 키(OpenRouter 발급 키 포함), Hugging Face 접근·갱신 토큰은 암호화하여 저장합니다. Codex 구독 인증 토큰·인증 파일은 PC에만 보관하며, 웹 로그인용 기기 코드·인증 주소는 인증 토큰과 구분하여 유효 기간(최대 15분) 동안만 서버에 임시 저장합니다.
3. 통신·계정 보호: 운영 환경에서 HTTPS와 Secure 세션·CSRF 쿠키를 사용하며 반복 로그인 실패와 가입 남용을 제한합니다.
4. 기록 관리: 운영자 조치를 감사 기록에 남기고 업무 변경을 추적합니다. 로그의 인증 토큰·비밀값을 가립니다.
5. 운영·보관 관리: 국내 자체 서버와 같은 서버 내 백업을 운영하고 백업 접근은 운영자로 제한합니다.

비밀번호·토큰의 해시와 일부 인증 정보의 암호화는 데이터 전체의 암호화와 구분됩니다. 백업 파일은 암호화하지 않습니다.

AI 요청에 필요한 업무 맥락은 요청자의 접근 권한 안에서 조립하고, 조직의 AI 자동완성 사용 여부를 확인합니다.

## 제14조 개인정보 사고 통지와 대응

통지에는 사고가 발생한 개인정보 항목, 시점과 경위, 이용자가 피해를 줄일 방법, 쿼넥트의 대응 조치와 피해 구제 절차, 담당 창구, 손해배상 청구·개인정보 분쟁조정 신청 방법을 포함합니다. 신고 의무가 있는 사고는 관계 기관에 신고합니다. 연락처를 알 수 없는 경우에는 법령에서 허용하는 공개 방식으로 통지를 갈음합니다.

AI 자동완성·태스크 후보 뽑기의 전송·국외 이전 안내는 다음과 같습니다. 허용 호스트 등록은 연결을 허용한다는 뜻일 뿐, 해당 AI 서버의 처리 조건을 법적으로 승인한다는 뜻이 아닙니다. 조직 AI는 조직마다 등록한 운영자가 다르므로 특정 사업자나 국가로 고정되지 않습니다. 주소 방식의 개인 AI도 등록한 서버에 따라 다릅니다. 공개 주소는 유달리 서버가 직접 요청하며, PC 내부·사설망의 개인 AI는 내 PC 연결 프로그램(udally-link)이 요청을 중계합니다. “Codex(내 구독, 내 PC)”는 서버 주소·키 없이 udally-link가 이용자의 PC에 OpenAI 구독 계정으로 로그인된 Codex CLI를 읽기 전용으로 실행하여 업무 자료를 OpenAI에 전송합니다. 유달리 서버는 해당 구독 인증 토큰을 받거나 보관하지 않습니다. 사용 순서에 따라 요청이 실패하면 다음 AI 경로에 같은 업무 내용이 전송될 수 있습니다.

유달리는 이 기능의 국외 처리 내용을 처리방침·이용약관에 고지하고 로그인 시 해당 문서의 적용 버전 동의 여부를 확인하는 기본 절차를 운영합니다. 계약 체결·이행에 필요한 국외 처리위탁·보관은 법 제28조의8제1항제3호의 요건에 따라 공개·고지하며, 그 밖에 별도 동의 등 다른 근거가 필요한 처리는 해당 법정 요건을 충족해야 합니다. 일반 문서 동의나 조직 관리자의 설정만으로 별도 동의가 필요한 제공·이전을 일괄 허용하는 것은 아닙니다. 다른 구성원의 개인정보를 보내는 경우 조직과 등록 이용자는 그 정보주체에 대한 적법한 절차를 이행합니다.
