AI와 함께한 일에도 담당자와 기록이 필요해요

이제 AI 없이 프로젝트를 진행하기 어려워졌어요. 팀원처럼 함께 일하고 내 조수로 결과물을 만드는 AI에게 무엇을 맡겼는지, 내가 무엇을 정했는지 대화만으로는 찾기 어려워요. 유달리는 팀의 태스크에 진행 상황과 결정 요지를 모읍니다.

정리 전

  • AI에게 맡긴 일이 대화에만 남아요.
  • GitHub에서 개발이 진행돼도 업무 보드는 따로 고칩니다.
  • 결과물을 보며 내 지시와 AI의 판단을 다시 찾게 돼요.

정리 후

  • 내 요청으로 AI가 만든 태스크에 담당자와 완료 조건을 둡니다.
  • 연결 규칙에 맞는 GitHub 활동이 태스크 상태를 바꿔요.
  • 내가 정한 내용과 AI가 판단한 내용을 나눠 확인합니다.

자라는 한 주

월요일에 고른 할 일이 개발과 검토를 거쳐 내 기록에 남는 한 주를 따라가요. 팀원과 AI가 함께한 과정에서 내가 정한 방향도 확인해 보세요.

  1. 월요일 아침

    씨앗

    지난주를 읽고 이번 주 할 일을 골라요

    오늘

    내가 맡은 일 가운데 지금 할 일을 고르세요.

    • 기한이 가까운 일과 기한을 넘긴 일이 오늘 목록에 자동으로 모여요.
    • 직접 담거나 오늘 하루만 빼서 목록을 조절합니다.
    • 맨 위의 미완료 태스크와 내 마감 달력을 살펴봐요.

  2. 월요일 오후

    싹

    고른 일을 AI에게 맡겨 착수해요

    AI 조수에게 맡길 일과 기록 방법

    AI는 내 지시에 따라 태스크를 계획하고 설정하며 진행 메모와 결정 요지를 남깁니다. 생성 초안은 내가 확인하고 대화에 없는 기한과 담당자는 비워 둬요. 태스크 담당자는 사람이며 AI는 내 권한 안에서 일합니다.

    내가 하는 말

    1. “이 기능을 태스크로 나누고 첫 작업에 착수해 줘.”

      분할안을 확인받아 태스크를 만들고 저장소가 연결돼 있으면 착수 스킬이 브랜치 이름을 정해 줘요.

    2. “작업 중 발견한 오류는 후속 태스크로 남겨 줘.”

      후속 태스크를 만들고 현재 작업의 진행 메모에 연결 번호를 남깁니다.

    3. “내 지시와 네 판단을 나눠 결정 기록으로 정리해 줘.”

      기록할 요지 후보를 보여 주고 내가 확인한 내용을 구분해 남겨요.

    유달리가 AI에게 주는 지침
    1. 코딩 에이전트용 스킬: /pm-start는 착수와 브랜치 이름을, /pm-pr은 태스크 번호를 담은 PR 설명 초안을 맡습니다.
    2. MCP 가이드: 도구 사용법과 사용자 입력·AI 판단을 나누는 방법, 브랜치·PR 연결 규칙을 안내합니다.
    3. 작업 전 질문: 구현에 영향을 주는 미결정 사항을 맥락과 선택지로 모아 묻도록 안내해요.

  3. 화요일 오후

    새싹

    개발한 내용을 검토하고 반영해요

    GitHub 활동과 태스크 상태 연결

    저장소가 연결된 프로젝트에서 AI에게 착수를 맡기면 태스크와 브랜치를 준비해요. AI 스킬이 태스크 번호를 담은 브랜치 이름과 PR 설명 초안을 정리하고 유달리는 연결된 활동에 맞춰 상태를 바꿉니다.

    1. AI에게 착수 맡기기

      TASK-12 초대 링크 만료 안내 문구 정리

      시작 전→진행 중

      브랜치 feat/초대-링크-안내-TASK-12

      /pm-start가 기한과 담당자를 확인하고 태스크를 진행 중으로 바꾸며 번호를 담은 브랜치 이름을 정해 줘요.

    2. 커밋 기록

      TASK-12 초대 링크 만료 안내 문구 정리

      진행 중

      연결된 PR 없음 · 커밋 2건

      태스크 번호가 담긴 커밋 메시지를 통해 개발 기록이 해당 태스크에 붙습니다.

    3. PR 초안 준비

      TASK-12 초대 링크 만료 안내 문구 정리

      진행 중

      TASK-12 초대 링크 만료 안내 추가

      /pm-pr이 결정 기록과 작업 내용을 읽고 태스크 번호를 포함한 PR 제목·설명 초안을 작성합니다.

    4. PR 열기

      TASK-12 초대 링크 만료 안내 문구 정리

      검토 대기

      #41 Open · 커밋 2건

      태스크 번호로 연결된 PR을 열면 검토 대기로 넘어가요.

    5. PR 머지

      TASK-12 초대 링크 만료 안내 문구 정리

      완료

      #41 Merged · 커밋 2건

      검토 대기를 거친 태스크는 연결된 PR이 머지되면 완료로 넘어갑니다.

    연결 규칙에 맞는 GitHub 활동이 태스크 상태를 바꿔요.

    GitHub 자동 연결은 TASK-n 규칙을 따르며 기한이 있는 태스크는 해당 번호가 든 브랜치 생성으로도 진행 중이 돼요. 저장소 규칙이 켜져 있어야 하고 커밋 연결만으로는 상태가 바뀌지 않습니다.

  4. 수요일 아침

    잎

    동료의 진행 상황을 함께 살펴요

    보드·부하

    누가 무엇을 맡았는지 팀이 함께 봐요.

    • 보드에서 태스크를 끌어 상태를 바꿉니다.
    • 사람별 부하를 보며 담당자와 기한을 조정합니다.
    • 로드맵에 마일스톤과 의존 관계를 정리해요.

    Discord 알림

    마감과 기다리는 일을 Discord에서 확인해요.

    • 마감 전과 당일, 기한 초과 알림을 담당자 DM으로 받습니다.
    • 조직 채널에 올라오는 주간 보고를 함께 읽습니다.
    • 오래 막힌 일과 검토를 기다리는 일을 관리자에게 알려요.

  5. 목요일 오후

    봉오리

    내가 정한 방향을 확인해요

    내 지시와 AI 판단을 나눈 결정 기록

    결과물만 보면 누가 어떤 방향을 정했는지 알기 어려워요. 태스크마다 선택의 요지와 근거를 남겨 내 역할을 확인합니다.

    • 사용자 입력: 내가 정한 요구사항과 방향 수정, AI에게 준 협업 방식 지시를 요약해요.
    • AI 작업 판단: 작업 중 AI가 선택한 방법은 별도로 남겨 내 결정과 구분합니다.
    • 본인 확인: AI가 추론한 내 결정은 확인 대기로 남으며 본인이 웹에서 확인해야 확정됩니다.

  6. 금요일 오후

    꽃

    한 주의 근거로 내 역할을 정리해요

    기록을 골라 내 AI 활용 포트폴리오를 써요

    내 결정 기록을 근거로 내가 정한 방향과 AI에게 맡긴 일을 보고서 형식으로 정리해요. 유달리가 외부 AI용 프롬프트를 만들고 내가 쓰는 AI가 글을 작성합니다.

    1. 기록 고르기

      내게 귀속되거나 내가 확인한 기록을 고르고 AI 판단은 작업 맥락으로 참고합니다.

      포트폴리오 출처

      내 결정 만료된 초대 링크에서 새 초대 요청 방법을 안내하도록 지시

      내 결정 구현 전 미결정 사항을 모아 질문하고 답을 기록하도록 지시

      AI 판단 · 프로젝트 맥락 검토 대기 전환 시각을 정렬 기준으로 선택

      선택한 출처로 AI 프롬프트 만들기
    2. 프롬프트

      고른 출처로 만든 프롬프트를 외부 AI에 붙여 넣어 초안을 받아요.

      AI에게 전달할 프롬프트

      프롬프트 복사
    3. 초안 저장

      AI가 쓴 마크다운을 유달리에 붙여 저장하고 편집한 뒤 파일로 내려받아요.

      AI가 작성한 Markdown

    초안은 소유자만 열람하는 비공개 문서입니다. AI 판단을 내 성과로 서술하지 않도록 프롬프트에서 안내해요.

AI에게 맡기는 범위는 사람이 정합니다

  1. 내 권한 안에서

    AI는 토큰을 발급한 사람의 권한을 넘지 못하며 조직의 AI 정책이 허용한 작업만 수행합니다.

  2. 변경 경로 기록

    변경 이력에는 누가 웹·API·AI·Discord·GitHub 중 어떤 경로로 바꿨는지 남습니다.

  3. 본인 확인

    AI가 추론한 내 결정은 본인이 웹에서 확인해야 확정되며 API나 MCP 토큰으로는 확인하지 못해요.

  4. 관리자 허용

    AI의 조직 설정 변경은 요청으로 올라가며 관리자가 웹에서 허용해야 적용됩니다.

개발은 GitHub에서 진행하고 팀의 할 일과 검토 상태도 함께 관리하고 싶어요.

  1. 저장소를 연결하고 AI 스킬로 착수해 브랜치와 PR 초안을 준비해요.
  2. PR 열림과 머지에 맞춰 검토 대기와 완료 상태를 반영합니다.
  3. 코딩 에이전트에게 태스크 계획과 결정 기록을 요청합니다.

개발 활동과 기획·디자인의 할 일을 같은 프로젝트에서 보고 싶어요.

  1. 담당자와 완료 조건을 적어 기획·디자인 태스크도 보드에서 관리합니다.
  2. 로드맵과 의존 관계로 함께 맞춰야 할 일정을 정리해요.
  3. 요청을 보내고 수락한 일을 태스크로 이어 관리합니다.

팀원마다 맡은 일과 AI의 도움을 받은 과정을 남기고 싶어요.

  1. 오늘 목록과 마감 달력으로 각자 맡은 일을 챙깁니다.
  2. 회의록과 프로젝트 문서에 함께 확인할 내용을 적어요.
  3. 내 결정 기록을 골라 개인 포트폴리오 초안의 근거로 써요.

저장소 없는 팀도 태스크·검토·회의록·문서·요청 기능을 씁니다. GitHub 자동화는 저장소를 연결한 프로젝트에서 동작해요.

GitHub 없이도 쓸 수 있나요?

네, 저장소 없이도 팀원 할 일과 검토, 회의록, 문서, 요청, 로드맵을 관리해요. GitHub 활동 연결과 상태 자동화는 저장소 연결이 필요합니다.

AI가 어디까지 일을 처리하나요?

내 지시에 따라 생성 초안을 확인받고 태스크를 만들거나 허용된 항목을 바꿔요. AI의 상태 변경은 검토 대기까지이며 완료는 사람이 처리합니다. 연결된 PR의 머지는 GitHub 규칙에 따라 완료로 반영돼요.

AI와 나눈 대화는 전부 기록되나요?

대화 원문을 수집하지 않으며 진행 메모와 결정 요지를 남깁니다. AI가 스킬·MCP 가이드를 따라 기록 도구를 호출하는 방식이에요. 요지 후보는 기록 전에 확인받고 비밀값처럼 보이는 내용은 거절합니다.

포트폴리오는 어떻게 만들고 누가 보나요?

기록을 골라 만든 프롬프트를 외부 AI에 보내고 받은 초안을 붙여 저장해요. 개인 경력 정리용 비공개 초안이며 소유자만 열람합니다. 유달리의 공개 페이지나 링크 공유 기능은 없어요.

무료인가요?

현재 무료로 이용하며 별도 요금제는 없습니다.

팀원은 어떻게 초대하나요?

가입 후 조직을 만들고 초대 링크로 팀원을 불러요. 가입에는 승인 절차가 없습니다.

GitHub 이슈도 자동으로 가져오나요?

이슈를 골라 태스크로 가져오는 방식부터 쓸 수 있어요. 자동 가져오기는 GitHub 조직에 앱을 설치하고 해당 설정을 켠 경우에만 적용됩니다. 라벨 조건에 맞고 GitHub 계정을 연결한 조직 멤버에게 배정된 새 이슈를 가져와요. 개인 계정 설치에는 적용되지 않습니다.

Discord를 꼭 연결해야 하나요?

연결 없이도 웹에서 팀의 일을 관리해요. DM 마감 알림과 조직 채널 주간 보고는 Discord 연동이 필요합니다.
